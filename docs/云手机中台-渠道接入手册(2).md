## §0 接入前必读

### §0.1 接入对象与场景速览

云手机中台 = Android 容器作为可编程资源对外租用的 SaaS Provider。

**核心数据模型:**

```
租户(tenantId,有父子层级)
  └─ 申请资源 → VM(vmId)← 物理宿主
      └─ 云手机(cpId)← Android 容器,一个 VM 可挂多个
          ├─ 装应用(来自 app_info 库)
          ├─ 绑代理(静态 / 动态 / TikTok / 自定义)
          ├─ 配仿真(国家 / 时区 / 语言 / GPS)
          ├─ 远程画面(WebRTC)
          └─ 跑脚本(一次性 task 或 周期 plan)
```

**接入主链路顺序(按依赖关系):**

```
1. 查规格库存(§1)→ 申请 VM(§1)→ 等 VM ONLINE
2. 上传 APK(§4)→ 创建云手机(§2,可预装应用 + 配代理 + 配仿真)
3. 启动云手机(§3)→ 装应用(§3)→ 绑代理(§3,自动跟随仿真)
4. 接管:WebRTC 看屏(§3) / ADB 接管(§3) / 文件管理(§3)
5. 自动化:上传脚本任务 / 周期计划(§7)
6. 全程:轮询任务状态(§8)
```

### §0.2 鉴权 — AKSK 签名详解

所有请求必须携带以下 Header。若通过中台网关接入,调用方只需要提供 AKSK 签名头;内部旁路头由网关或内部调用链处理,不要在公网侧自行伪造。

| Header | 类型 | 说明 |
|---|---|---|
| `X-Access-Key` | string | 中台分配的 AK |
| `X-Timestamp` | string | Unix 毫秒时间戳(注意时间窗 5 分钟,服务器拒绝过老请求) |
| `X-Signature` | string | HMAC-SHA256 签名 |
| `X-Trace-Id` | string | 建议填写;调用方生成的链路追踪 ID,排障时需提供 |
| `Content-Type` | string | `application/json`(文件上传为 `multipart/form-data`) |

#### 签名算法

```
$TS = unix 毫秒时间戳
$NONCE = 随机串
$BODY_MD5 = MD5(request_body)  // GET 时为空字符串的 MD5
$STRING_TO_SIGN = "{HTTP_METHOD}\n{PATH}\n{TS}\n{NONCE}\n{BODY_MD5}"
$SIG = HMAC-SHA256(Secret_Key, $STRING_TO_SIGN) → 十六进制小写
```

#### Java 示例

```java
String stringToSign = method + "\n" + path + "\n" + timestamp + "\n" + nonce + "\n" + md5Hex(body);
SecretKeySpec keySpec = new SecretKeySpec(secretKey.getBytes(StandardCharsets.UTF_8), "HmacSHA256");
Mac mac = Mac.getInstance("HmacSHA256");
mac.init(keySpec);
String signature = bytesToHex(mac.doFinal(stringToSign.getBytes(StandardCharsets.UTF_8)));
```

#### Python 示例

```python
import hmac, hashlib
string_to_sign = f"{method}\n{path}\n{ts}\n{nonce}\n{md5_hex(body)}"
signature = hmac.new(secret_key.encode(), string_to_sign.encode(), hashlib.sha256).hexdigest()
```

#### 注意

- AKSK 时间戳超窗会返回 401,原因子码见 §0.5。
- AKSK 签名错误返回 401,请优先检查签名串、请求体 MD5、Nonce 和 Secret Key。
- 推荐使用客户端 SDK 自动签名,避免手动拼串出错。

### §0.3 公共响应外壳

所有接口统一返回 `CallResult<T>` 结构:

```json
{
  "code": "SUCCESS",
  "message": "成功",
  "data": <T>,
  "traceId": "abcd-..."
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| code | string | 业务结果码。`SUCCESS` 表示成功;其他值表示业务失败(详见 §0.5);该字段不承载 HTTP 状态码 |
| message | string | 描述信息(失败时含错误细节) |
| data | T \| null | 真正的业务数据 |
| traceId | string | 与请求 `X-Trace-Id` 对应 |

**判断规则:** HTTP 状态码表示协议层/框架层状态;业务成败以响应体 `code` 为准。失败时 `code` 返回具体业务码或通用 `FAIL`;客户端应按业务码做分流,并结合 `message` 与 `traceId` 排障。

**排障最佳实践:**
- 调用失败时,**保留 traceId** 提供给中台支持
- 调用成功但行为异常时(异步操作),**保留 traceId + workflowId**

**例外:** §3.8 `/phone-command/file-download-stream` 文件下载接口**不走 CallResult 外壳**,直接返回二进制流 + HTTP 头(详见 §3.8)。

### §0.4 分页约定

中台所有分页接口走 `PageRequest`:

```json
{
  "page": 1,         // 注意: 注意请求里字段名是 page
  "pageSize": 20
}
```

分页响应走 `PageResponse<T>`:

```json
{
  "data": [...],
  "pageNum": 1,      // 注意: 注意响应里字段名是 pageNum(不一致!历史包袱)
  "pageSize": 20,
  "totalSize": 142   // 部分接口字段名为 total
}
```

**重要提示:**
- 请求字段名 `page`,响应字段名 `pageNum`,**不一致是历史包袱,不要写错**
- 若错写请求为 `pageNum`,**中台会默认忽略并返回第 1 页**(不会报错,排障困难)
- 个别接口(§2.3/§2.4 v1 回填)用 `pageNum` 作为请求字段,差异详见各接口章节

### §0.5 错误码体系

本手册按接入排障需要整理常见错误码。`code` 是业务结果码,不等同于 HTTP 状态码;业务错误码统一读取 `code`。客户端应优先展示 `message`,并记录 `traceId` 供排障。

#### 通用业务码

| code | HTTP | 含义 | 排查方向 |
|---|---|---|---|
| `SUCCESS` | 200 | 成功 | — |
| `FAIL` | 200/500 | 通用业务失败 | 看 message + traceId 提工单 |
| `DATA_NOT_EXIST` | 404 | 资源不存在 | 检查 ID 是否正确 |
| `OPERATION_FAILED` | 500 | 操作失败 | 看 message |

#### 鉴权类错误码

| code | HTTP | 含义 | 排查方向 |
|---|---|---|---|
| `AKSK_NOT_FOUND` | 401 | AK 不存在 | 联系中台检查 AK 是否签发 |
| `AKSK_DISABLED` | 401 | AK 已禁用 | 联系中台启用 / 重新申请 |
| `AKSK_EXPIRED` | 401 | AK 已过期 | 联系中台续期 |
| `SIGNATURE_INVALID` | 401 | 签名不匹配 | 检查签名算法 / 拼串顺序 / Secret Key |
| `TIMESTAMP_OUT_OF_WINDOW` | 401 | 时间戳超窗(±5 分钟) | 检查客户端时钟同步 |
| `QUOTA_EXCEEDED` | 429 | 调用次数超 quota | 联系中台扩容 / 降低调用频率 |
| `RATE_LIMITED` | 429 | 单接口限流(详见各接口 QPS) | 客户端做退避 |

> **说明:** 客户端应以 `code + message + traceId` 为主线排障;`code` 是业务码,不是 HTTP 状态码。

#### 上传/任务类错误码

| code | HTTP | 含义 | 排查方向 |
|---|---|---|---|
| `UPLOAD_SESSION_EXPIRED` | 404 | 上传任务不存在或已过期(Redis TTL 24h) | 重新走 §4.2 启动上传 |
| `OSS_FAILED` | — | 上传 OSS 失败 | 看 message |

### §0.6 接入前准备清单

接入前请向中台对接人确认以下材料就绪:

- [ ] AK / Secret Key 已签发,**生产环境建议申请限期密钥(默认 90 天),禁用永久有效**
- [ ] 测试环境域名 + 生产环境域名
- [ ] 至少一个测试 VM 资源已开通(用于跑 §1 资源申请)
- [ ] 至少一个测试镜像 ID + 启动方案 ID(用于跑 §2 创建云手机)
- [ ] 是否需要使用代理:确认中台开通的代理供应商(IPIPGO / SHENLONG / IPVIBE 等)
- [ ] 是否需要 TikTok 专属代理:确认 TikTok 套餐已开通
- [ ] 是否需要 **WebRTC 远程画面**:需确认 WebRTC 信令协议、票据生命周期和前端接入方式 — 详见 §3.6
- [ ] 是否需要 **ADB 通道接管**:需确认 ADB token、客户端命令和连接代理协议 — 详见 §3.5.2
- [ ] 是否需要自动化脚本:需确认脚本模板上传、审核和导入方式 — 详见 §7.5.1

### §0.7 时区与时间格式约定

- 所有 LocalDateTime 字段格式:`"2026-06-04T10:00:00"`(无时区,**中台默认按北京时间解析**)
- 个别字符串字段:`"2026-06-04 10:00:00"`(空格分隔,不是 `T`)
- **跨境场景重要提示**:`/autoscript/task/create-scheduled` 等接口的 `publishTime` 当前按中台服务时区解析,跨境租户场景需在客户端自行完成时区转换。


### §0.8 生产接入与上线验收标准

| 项目 | 标准做法 |
|---|---|
| Base URL | 测试 / 生产域名由中台对接人提供;本文示例统一使用 `https://midplat.example.com` 占位 |
| API 版本 | 对外路径以 `/open/api/vendor/v1` 为主;客户端封装时不要把 `v1` 写死在业务逻辑中 |
| 超时 | 普通查询 10-30s;文件、应用解析、批量代理检测按章节设置 300s |
| 重试 | 网络超时 / 429 / 5xx 可退避重试;创建、销毁、续期、购买等写操作重试前先用业务 ID 或列表查询确认结果 |
| 轮询 | 异步操作间隔 5-10s;终态后停止;同一批任务优先用批量查询 |
| 限流 | 遇到 `RATE_LIMITED` / HTTP 429 必须指数退避;不要用秒级以下轮询压测生产环境 |
| 幂等 | 查询类自然幂等;写操作未明确提供幂等键时,客户端需保留业务请求号并在重试前查询状态 |
| 日志脱敏 | 不记录 Secret Key、代理密码、ADB token、WebRTC authToken;排障时提供 `traceId` 和脱敏请求体 |
| 上线验收 | 至少跑通 §10.1 一条完整链路,并覆盖鉴权失败、限流、异步超时、部分成功、文件上传失败恢复等场景 |

> 为了节省篇幅,部分后续 curl 示例只展示核心 Header;实际请求必须按 §0.2 携带完整鉴权 Header。

### §0.9 推荐公开入口与路径规则

对外接入优先使用带 `/open/api/vendor/v1` 前缀的公开入口。若正文中为了阅读简洁出现服务内相对路径,实际公网调用时仍需按本节规则拼接完整路径。

## §1 资源申请

### §1.1 场景速览

**业务诉求:** 在云手机创建之前,先申请底层的虚机(VM)资源。

**接口编排:**

```
Step 1: 查询全规格库存       → /resource-group/all-spec-stocks
Step 2: 查最大可开数         → /resource-group/max-openable
Step 3: 申请资源组(开 VM)   → /resource-group/apply           异步
Step 4: 等 VM ONLINE         → /server/page 轮询查询           补充
Step 5: 拿到可用 VM,进入 §2 创建云手机
```

### §1.2 接口详解

---

#### §1.2.1 查询全规格库存

**作用:** 列出所有可用规格(CPU/内存/存储/带宽/GPU)及当前库存数,供 §1.2.2 / §1.2.3 选规格用。

| | |
|---|---|
| **HTTP** | `GET /open/api/vendor/v1/resource-group/all-spec-stocks` |
| **超时建议** | 30s |
| **调用时机** | 接入流程 Step 1 / 产品调研选规格 |

##### 入参(Query)

| 字段 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `serviceType` | string |  | `OPEN` | `OPEN`=本租户资源池库存 / `APPLY`=父租户资源池库存 |

##### 请求示例

```bash
curl -X GET "https://midplat.example.com/open/api/vendor/v1/resource-group/all-spec-stocks?serviceType=OPEN" \
  -H "X-Access-Key: $AK" -H "X-Timestamp: $TS" -H "X-Signature: $SIG"
```

##### 出参(`data` 字段为数组)

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `specId` | int | N | 规格 ID,后续 §1.2.2/§1.2.3 用 |
| `specName` | string | N | 规格名(如 `1c2g16g`) |
| `core` | int | Y | CPU 核数 |
| `memory` | int | Y | 内存(GB) |
| `storage` | int | Y | 存储(GB) |
| `bandwidth` | int | Y | 带宽(Mbps) |
| `gpuCount` | int | Y | GPU 数 |
| `card` | int | Y | 显卡数 |
| `gpuInfoList` | object[] | Y | GPU 详细信息(`model / brand / cardCount`) |
| `stock` | int | N | 当前库存数 |

##### 完整响应示例

```json
{

  "message": "成功",
  "data": [
    {
      "specId": 23,
      "specName": "1c2g16g",
```

| 值 | 含义 | 使用场景 |
|---|---|---|
| `OPEN` | 本租户资源池库存 | 渠道侧自有资源 |
| `APPLY` | 父租户资源池库存 | 渠道通过父租户申请资源时 |

无特定错误码,失败走通用 `500`。详见 §0.5。

#### §1.2.2 查询最大可开数

**作用:** 给定租户 + 规格 + 场景,返回**实际可开**的云手机台数 = min(库存,租户配额剩余)。

| | |
|---|---|
| **HTTP** | `GET /open/api/vendor/v1/resource-group/max-openable` |
| **超时建议** | 30s |
| **调用时机** | 接入流程 Step 2 / 创建云手机前预检 |

##### 入参(Query)

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `tenantId` | int | ✓ | 申请方租户 ID |
| `specId` | int | ✓ | 规格 ID,来自 §1.2.1 |
| `scenarioId` | int | ✓ | 场景 ID,业务方提供 |

##### 请求示例

```bash
curl -X GET "https://midplat.example.com/open/api/vendor/v1/resource-group/max-openable?tenantId=7&specId=23&scenarioId=1" \
```

##### 出参

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `maxOpenable` | int | N | 实际可开数 = min(stock, quotaLeft) |
| `stock` | int | Y | 库存数 |
| `quotaLeft` | int | Y | 租户配额剩余 |

##### 完整响应示例

```json
{
  "code": "SUCCESS",
  "message": "成功",
  "data": { "maxOpenable": 12, "stock": 18, "quotaLeft": 12 },

```

#####  重要陷阱:`maxOpenable=0` 三义性混淆

`maxOpenable=0` 实际混合 3 种业务含义,**渠道侧必须分情况处理**:

| 情况 | 判定条件 | 渠道动作 |
|---|---|---|
| 真的库存为零 | `stock=0 且 quotaLeft>0` | 等待补货,可重试 §1.2.1 |
| 中台未给该租户配置该规格 | `stock>0 且 quotaLeft=0` 且未签约 | **联系中台对接人开通** |
| 租户配额耗尽 | `stock>0 且 quotaLeft=0` 且已签约 | **申请配额扩容** |

**后续可能补充 `zeroReason` 字段**,届时可直接读字段判断。

|---|---|---|---|
| `DATA_NOT_EXIST` | 404 | `specId` 或 `scenarioId` 不存在 | 检查 ID 来源 |

##### 相关枚举(`vmStatus` — 8 个)

| 值 | 含义 | 渠道动作建议 |
|---|---|---|
| `ONLINE` | 在线就绪 | ✓ 可进 §2 创建云手机 |
| `OFFLINE` | 离线 | 联系中台 |
| `REBOOTING` | 重启中 | 继续轮询 |
| `RESETTING` | 重置中 | 继续轮询 |
| `REPLACING` | 替换中 | 继续轮询 |
| `UPGRADING` | 升级中 | 继续轮询 |
| `AGENT_OFFLINE` | 控制器离线 | 联系中台 |
| `MAINTENANCE` | 维护中 | 等中台维护完成 |

#####  申请后轮询策略(说明)

- **轮询间隔:** 5-10 秒
- **总等待时长:** ≤ 5 分钟,超时判失败
- **判定 ONLINE:** 申请提交的所有 vmId 都在响应里且 vmStatus=ONLINE
- **判定失败:** 任一 vmId vmStatus=OFFLINE/AGENT_OFFLINE,或超时
- 后续可能支持 webhook 推送 VM 就绪事件,届时可订阅事件免轮询

无特定错误码,失败走通用 `500`。

### §1.4 常见问题

| 问题 | 排查方向 |
|---|---|
| `maxOpenable=0` 但 `stock` 非零 | 大概率租户未配置该规格,联系中台对接人开通 |
| §1.2.3 返回 `inserted < count` | 调 §1.2.1 看库存,确认是否资源不足;同时检查 quotaLeft |
| §1.2.4 轮询 5 分钟仍未 ONLINE | 联系中台,可能 VM 已 INIT_FAILED,资源未自动回收(尝试 §1.2.5 重置) |
| §1.3.3 返回空数组 | 检查 planId 是否来自 §1.3.2,且方案未禁用 |
| §1.3.4 机型 status=0 | 该机型在当前镜像下不可用,选其他机型 |

### §2.6 查询云手机(v2 主推)

**作用:** v2 主查询接口,支持丰富的多维过滤,**返回字段是 v1 的 3 倍**(80+ 字段分 11 组)。**所有新业务请用本接口**。

| | |
|---|---|
| **HTTP** | `POST /open/api/vendor/v1/cloud-phone/page` |
| **超时建议** | 30s |
| **调用时机** | 列表页 / 状态轮询 / 代理绑定后同步 / 任务前云手机校验 |

**注意分页字段:** 请求是 `page`(不是 `pageNum`)。

```json
{
  "page": 1,
  "pageSize": 50,
  "cpIds": ["cp-xxx-001"],
  "statusList": ["NORMAL", "STOPPED"]
}
```

#### 常用过滤字段

| 字段 | 说明 |
|---|---|
| `cpId / cpIds` | 精确匹配 |
| `vmId / vmUid` | 按宿主 VM 查 |
| `status / statusList` | 按云手机状态过滤(详见枚举) |
| `imageId / imageName / androidVersion` | 按镜像 |
| `specId / specName` | 按规格 |
| `zoneId / zoneName` | 按可用区 |
| `tenantId / tenantName` | 按租户(父租户可查子租户) |
| `createTimeStart / createTimeEnd` | 按创建时间窗 |

#### 响应关键字段(分 11 组,共 80+ 字段)

按业务需要取用:

| 组 | 关键字段 |
|---|---|
| ID 与来源 | `id / cpId / cpSource / vmId / vmUid / vmIp / pmId / currentTenantId` |
| VM 物理资源 | `vmStatus / vmCpu / vmMemory / vmStorage / vmGpuCount` |

#### 云手机状态枚举(18 个,说明"客户层 vs 底层"分组)

 **说明的 18 状态完整对应表(原始资料仅给中文名,无触发场景 / 客户层映射)**:

| 原始枚举 | 中文语义 | 客户层映射 | 典型触发场景 | 渠道动作建议 |
|---|---|---|---|---|
| `NORMAL` | 已开机 | **RUNNING** | 启动完成后的稳定状态 | ✓ 可对接业务 |
| `INITIALIZING` | 正在初始化 | **CREATING** | §2.2 创建云手机后,容器尚未启动 | 继续轮询,预期 1-2 分钟内变 STARTING |
| `STARTING` | 正在开机 | **CREATING** | §3.1 启动接口调用后,或 INITIALIZING 完成后 | 继续轮询,预期 ≤1 分钟变 NORMAL |
| `INIT_FAILED` | 初始化失败 | **FAILED** | §2.2 创建后底层资源 / vm-agent 异常 | 查 `exceptionReason`,联系中台 |
| `STOPPING` | 正在关机 | **STOPPED**(过渡态) | §3.1 停止接口调用后,几秒内变 STOPPED | 继续轮询,预期 ≤30 秒变 STOPPED |
| `STOPPED` | 已关机 | **STOPPED** | §3.1 停止完成,或 STOPPING 完成 | 可调 §3.1 启动重新唤醒 |
| `REBOOTING` | 正在重启 | **CREATING**(过渡态) | §3.1 重启接口调用后 | 继续轮询,预期 1-2 分钟变 NORMAL |
| `RESETTING` | 正在重置 | **CREATING**(过渡态) | §2.4 一键新机 / 重置调用后 | 继续轮询,数据已清空,预期 2-3 分钟变 NORMAL |
| `REPLACING` | 换机中 | **CREATING**(过渡态) | 运维侧把云手机迁到新 VM(对渠道透明) | 继续轮询,预期数分钟变 NORMAL |
| `UPDATING` | 正在更新 | **CREATING**(过渡态) | 镜像 / 配置更新中 | 继续轮询 |
| `MAINTAINING` | 维护中 | **FAILED**(暂不可用) | 中台主动运维(发布 / 故障处理) | 暂停业务调用,联系中台确认维护窗口 |
| `FAULTED` | 异常 | **FAILED** | 通用故障终态 | 查 `exceptionReason / reasonDesc`,联系中台 |
| `VM_RESETTING` | 服务器重置中 | **FAILED**(暂不可用) | 底层 VM 被运维侧重置,云手机不可用 | 等待 VM ONLINE,云手机会回 NORMAL |
| `VM_OFFLINE` | 服务器离线 | **FAILED** | 底层 VM 故障 / 网络断开 | 联系中台 |
| `VM_UPGRADING` | 服务器升级 | **FAILED**(暂不可用) | 底层 VM 升级中 | 等待 VM 升级完成 |
| `AGENT_OFFLINE` | 控制器(vm-agent)离线 | **FAILED** | vm-agent 进程异常,云手机失联 | 联系中台 |
| `DISTROYING` 历史兼容 | 正在销毁(协议级拼写错!应为 DESTROYING) | **DESTROYED**(过渡态) | §2.3 销毁后过渡几秒 | ✓ 客户端代码必须按 `DISTROYING` 错拼写匹配,等待 v1 退役后修正 |
| `DESTROYED` | 已销毁 | **DESTROYED** | §2.3 销毁完成 | 资源已释放,不可再用 |

**客户层聚合视图(便于做监控大屏 / 状态过滤):**

| 客户层语义 | 包含的原始枚举 | 客户端业务逻辑建议 |
|---|---|---|
| **CREATING**(创建中) | INITIALIZING / STARTING / REBOOTING / RESETTING / REPLACING / UPDATING | 显示进度条 / 等待,业务调用排队 |
| **RUNNING**(运行中) | NORMAL | ✓ 接受所有业务调用 |
| **STOPPED**(已关机) | STOPPING / STOPPED | 业务调用拦截,提示启动 |
| **FAILED**(异常 / 暂不可用) | INIT_FAILED / FAULTED / MAINTAINING / VM_RESETTING / VM_OFFLINE / VM_UPGRADING / AGENT_OFFLINE | 业务调用拦截,提示用户/触发告警 |
| **DESTROYED**(已销毁) | DISTROYING / DESTROYED | 从本地缓存移除该 cpId |

**建议:** 你的客户端按客户层 5 状态做业务逻辑,把 18 状态作为 sub-status 辅助显示。

 **协议级拼写错(历史兼容)**: `DISTROYING`(应为 DESTROYING),wire 协议已固化。**接入时必须按错误拼写匹配**,等待中台 v1 退役统一修正。

#### 特定错误码

| code | HTTP | 触发场景 | 处理建议 |
|---|---|---|---|
| `OPERATION_FAILED` | 500 | 入参超出 100 上限(批量查询时)/ pageSize 超限 | 分批 |
| `RATE_LIMITED` | 429 | 轮询过频 | 客户端退避 |

### §2.7 v1 兼容查询(字段回填)

**作用:** 当 §2.6 v2 响应里某些字段为空时,用本 v1 接口回填。**v1 不应作为主查询路径,仅作为字段补全工具**。

##### 入参(Body)

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|

### §2.10 常见问题

| 问题 | 排查方向 |
|---|---|
| 创建后云手机状态卡在 `INITIALIZING` | 等待 1-2 分钟,或查 `vmStatus` 是否非 `ONLINE` |

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `cpIds` | **object[]** | ✓ | 注意: **是对象数组(不是字符串数组!)**,每项 `{cpId, proxy}` |
| `cpIds[].cpId` | string | ✓ | 单台云手机 ID |
| `cpIds[].proxy` | object \| null |  | 代理对象;**传 `null` = 解绑该云手机的代理** |
| `cpIds[].proxy.proxyId` | number |  | 已有代理 ID(走 ADDED 模式) |
| `cpIds[].proxy.proxyOrderType` | string |  | `STATIC` / `DYNAMIC` / `TIKTOK` |

```bash
curl -X POST "https://midplat.example.com/open/api/vendor/v1/cloud-phone/proxy/batch-update" \
  -H "X-Access-Key: $AK" -H "X-Timestamp: $TS" -H "X-Signature: $SIG" \
  -d '{
    "cpIds": [
      {
        "cpId": "cp-aaa",
        "proxy": {
          "proxyId": 9001,
          "proxyOrderType": "STATIC",
          "host": "us-proxy.example.com",
          "port": 1080,
          "username": "u",
          "password": "***",
          "type": 1
        }
      },
      { "cpId": "cp-bbb", "proxy": null }
    ],
    "regionFollowProxy": true,
    "timezoneFollowProxy": true,
    "languageFollowProxy": true
  }'
```

##### 出参

返回 `data: null`,**仅代表 push 已下发**,代理是否实际生效需异步观察。

##### 完整响应示例

```json
{ "code": "SUCCESS", "message": "成功", "data": null, "traceId": "abc-123" }
```

#####  重要陷阱(说明,5 条)

1. **`cpIds` 字段名是对象数组**,与其他接口的 `string[]` cpIds 完全不同。**别用 `["cp-aaa", "cp-bbb"]` 形式调用,会失败**
2. 本接口**同步声明但实际异步串行执行**,300s 超时是正常 — **客户端把超时设到 300s**
3. 200 OK **不代表代理已生效**,只代表 push 已下发。**当前无状态查询接口**,只能轮询 §2.6 看 `proxyInfo.detectionTime / testingResult` 间接观察
4. **解绑代理有两条不一致路径**:本接口传 `proxy: null` 是主路径,§2.4 重置接口的 `keepbindAgent: false` 是副作用路径。**只用本接口的主路径**
5. **批量部分失败无感知**:返回 `data: null`,即使 100 台里 30 台失败,客户端拿 200 OK 无法判别 — 后续会补充 successCpIds / failedCpIds 返回

##### 仅修改仿真不修改代理:不支持

**当前没有"只改仿真"的独立接口**。若要单独改仿真:
- 重置 §2.4 时重新指定仿真参数(粗暴,数据全清)
- 解绑代理再重绑同代理 + 不同 followProxy 标志(变通)
- **后续可能支持独立仿真修改接口**

##### 特定错误码

| code | HTTP | 触发场景 | 处理建议 |
|---|---|---|---|
| `DATA_NOT_EXIST` | 404 | cpId / proxyId 不存在 | 检查 ID |
| `OPERATION_FAILED` | 500 | push 失败 / 代理状态异常 | 看 message,重试 |

### §3.6 WebRTC 接入

WebRTC 远程画面接入涉及 **3 个组件**,渠道需依次集成:

```
[1] 鉴权票据(REST)
    ↓ 拿 authToken / signalUrl / pushStreamUrl
[2] 信令通道(WebSocket) 服务已存在,协议规范需单独确认
    ↓ 交换 SDP / ICE candidate
[3] 媒体通道(WebRTC PeerConnection + 可选 RTMP 推流)
```

---

#### §3.6.1 拿 WebRTC 鉴权票据(REST 接口) 已对外

**作用:** 拿一次性 `authToken` + `signalUrl`(WebSocket 信令地址)+ `pushStreamUrl`(媒体推流地址)。**这是 WebRTC 链路的入口接口**。

|              |                                                    |
| ------------ | -------------------------------------------------- |
| **HTTP**     | `POST /open/api/vendor/v1/cloud-phone/webrtc-auth` |
| **超时建议** | 30s                                                |
| **调用时机** | 用户点击"连接"按钮时;authToken 失效后续期          |

##### 入参(Body)

| 字段    | 类型     | 必填 | 说明                                              |
| ------- | -------- | ---- | ------------------------------------------------- |
| `cpIds` | string[] | ✓    | 待接入的云手机 ID 列表(可批量,但通常单次接入一台) |

##### 请求示例

```bash
curl -X POST "https://midplat.example.com/open/api/vendor/v1/cloud-phone/webrtc-auth" \
  -H "X-Access-Key: $AK" -H "X-Timestamp: $TS" -H "X-Signature: $SIG" \
  -d '{ "cpIds": ["cp-aaa"] }'
```

##### 出参(`data` 为数组)

| 字段              | 类型    | 可空 | 说明                                              |
| ----------------- | ------- | ---- | ------------------------------------------------- |
| `cpId`            | string  | N    | 云手机 ID 回放                                    |
| `vmId`            | string  | N    | 宿主 VM ID                                        |
| `zoneId`          | int     | Y    | 可用区 ID                                         |
| `pushStreamUrl`   | string  | N    | 媒体推流地址(RTMP),用于 §3.6.3                    |
| `signalUrl`       | string  | N    | **WebRTC 信令地址(WebSocket wss://)**,用于 §3.6.2 |
| `authToken`       | string  | N    | 一次性 token,用于信令通道握手                     |
| `hasRunningTask`  | boolean | Y    | 当前是否有运行中的脚本任务(WebRTC 期间避免触发)   |
| `hasUpcomingTask` | boolean | Y    | 是否有即将执行的脚本任务                          |

##### 完整响应示例

```json
{
  "code": "200",
  "message": "成功",
  "data": [{
    "cpId": "cp-aaa",
    "vmId": "vm-001",
    "zoneId": 1,
    "pushStreamUrl": "rtmp://stream.example.com/live/cp-aaa",
    "signalUrl": "wss://signal.example.com/ws",
    "authToken": "tk-xxxxxxxx",
    "hasRunningTask": false,
    "hasUpcomingTask": false
  }],
  "traceId": "abc-123"
}
```

#####  `authToken` 一次性语义(说明,原始资料未明)

- **TTL**:RTC 信令一次交换后即失效;**具体时长建议向中台对接人确认**(估计 5 分钟内)
- **续期**:失效后重新调本接口,**不要预取缓存**(用户点击连接时再调)
- **多 client 协同看屏**:当前是否允许同一 authToken 被多个客户端使用 — **未明确**,建议每个 client 独立调本接口
- **吊销**:无主动吊销接口,只能依赖一次性失效

#####  票据敏感字段安全(后续可能支持)

`authToken / signalUrl / pushStreamUrl` 是敏感凭据,但文档未声明:

- 是否走 HTTPS(默认假设,但应正式声明)
- 日志中是否脱敏
- trace 链路中是否记录

合规审计型客户(SOC2 / ISO 27001)对接前请向中台对接人确认。。

##### 特定错误码

| code               | HTTP | 触发场景                         | 处理建议       |
| ------------------ | ---- | -------------------------------- | -------------- |
| `DATA_NOT_EXIST`   | 404  | cpId 不存在                      | 检查 cpId 来源 |
| `OPERATION_FAILED` | 500  | 云手机不在 NORMAL 状态(如已销毁) | 先 §2.6 查状态 |

---

#### §3.6.2 信令通道协议(WebSocket) 需单独确认

>  **重要说明:本节为"需确认协议"的章节占位**
>  中台**已实现完整的信令通道服务**(由 §3.6.1 返回的 `signalUrl` 提供),但**信令通道协议规范当前未对外文档化**。这是渠道接入 WebRTC 时的关键缺口。

##### 当前已知信息

| 项           | 已知                                                         |
| ------------ | ------------------------------------------------------------ |
| **服务来源** | §3.6.1 webrtc-auth 接口返回的 `signalUrl`(`wss://signal.example.com/ws` 格式) |
| **协议类型** | WebSocket(明文加密,wss://)                                   |
| **认证方式** | 一次性 `authToken`(来自 §3.6.1)— 具体如何携带(Header / Query / 首条消息)**未明确** |
| **用途**     | 客户端与中台信令服务交换 WebRTC SDP / ICE candidate,以建立媒体通道 |

##### 需单独确认的内容

接口已存在,但需要中台**对外发布以下协议规范**才能让渠道真正接入:

| 需确认内容                 | 说明                                                         |
| -------------------------- | ------------------------------------------------------------ |
| **WebSocket 握手认证方式** | authToken 通过 Header / Query / 首条消息中哪种方式传递       |
| **消息格式定义**           | JSON Schema 还是 Protobuf 字段名约定                         |
| **完整事件流程图**         | client 连接 → 发送 offer / answer / candidate → 接收 server 消息 → 断开 — 全流程时序图 |
| **SDP 交换具体步骤**       | offer/answer 哪边先发 媒体协商参数(codecs / bitrate)由谁决定 |
| **ICE candidate 处理规则** | trickle 模式还是 vanilla 模式 candidate 类型(host / srflx / relay)的处理优先级 |
| **STUN / TURN 服务器配置** | 客户端需要配什么 STUN / TURN(内部协议资料                    |
| **心跳与断线重连**         | 是否需要心跳 间隔多少 断线后是否可恢复                       |
| **协同看屏多客户端**       | 同一 cpId 多客户端同时接入是否支持 互斥规则                  |
| **常见错误事件**           | 鉴权失败 / 信令超时 / 媒体协商失败的事件格式与码值           |

##### 渠道当前获取协议规范的路径(过渡方案)

在中台正式对外文档化之前,渠道可:

1. **联系中台对接人**:索取**「WebRTC 信令通道协议规范」内部文档**,通常包含上述需确认内容的详细描述
2. **参考既有客户的集成代码**:中台 PC 端 / 移动端的 WebRTC 接入实现是参考样本(协议消息格式与实际行为一致)
3. **提工单咨询排障**:接入过程中遇到 WebRTC 连接失败,联系中台 SA / 客户成功提工单

> 注意: **接入风险提示**:在 WebRTC 信令协议正式对外发布前,渠道接入需以中台书面提供的协议规范为准,并在接入评审中确认协议变更通知机制。

#### §3.6.3 媒体推流(RTMP / WebRTC SRT)

##### 当前已知信息

`pushStreamUrl`(由 §3.6.1 返回)格式:`rtmp://stream.example.com/live/{cpId}`

这是**云手机端推送音视频流的入口**,客户端通过 §3.6.2 信令通道与媒体服务建立 WebRTC PeerConnection 后,即可拉取该流。

##### 已知用法

| 场景                  | 用法                                                         |
| --------------------- | ------------------------------------------------------------ |
| **WebRTC 浏览器接入** | 客户端无需直接访问 RTMP URL,通过 PeerConnection 自动拉流     |
| **第三方推流转发**    | 部分高级场景(如直播切片转推)可由中台从 cloud phone → RTMP → 第三方 CDN 链路实现 |

##### 需单独确认的内容

- RTMP URL 鉴权方式(authToken 是否需要追加在 URL Query)
- 推流参数(媒体编码 / bitrate / fps)是否可配置
- 多客户端同时拉流的并发上限

#### §3.8.3 流式下载文件  错误码兼容

**作用:** 从云手机下载单个文件。

| | |
|---|---|
| **HTTP** | `POST /open/api/vendor/v1/phone-command/file-download-stream` |
| **超时建议** | 300s |
| **调用时机** | 文件管理面板单文件下载 |


- `Content-Disposition: attachment; filename="report.pdf"`
- `Content-Length`:文件字节数
- Body:文件二进制

**失败(HTTP 500):**
- Body:UTF-8 编码的错误描述(纯文本,非 JSON)

#####  错误码体系塌缩到 500(说明)

| 真实场景 | 当前行为 | 建议兼容行为 |
|---|---|---|
| 文件不存在 | 500 + 模糊错误 | 404 + `FILE_NOT_FOUND` |
| 权限不足 | 500 + 模糊错误 | 403 + `PERMISSION_DENIED` |
| vm/container 不存在 | 500 + 模糊错误 | 422 + `CONTAINER_NOT_FOUND` |
| 路径不合法(`../etc/passwd`) | 500 + 模糊错误 | 400 + `PATH_INVALID` |
| 租户配额耗尽 | 500 + 模糊错误 | 429 + `QUOTA_EXCEEDED` |

**当前渠道规避方案:** 下载前先用 §3.8.1 `file-list` 确认文件存在 + 路径正确,降低失败概率。

当前**仅有 500**,无差异化。

## §4 应用管理

### §4.1 场景速览

**业务诉求:** 渠道侧管理 APK 应用(上传 / 安装 / 预装,**无下载**)。

**接口编排:**

```
上传向导(7 步):同租户名校验 → 启动上传(秒传逻辑) → 上传分片 → 合并 → 解析 APK → 提交创建 → 查上传状态
装机:  §3.7
预装:  §2.2 创建云手机时 appIds 字段
查列表:§3.7.3 / §4.6
```

### §4.2 上传向导(7 步主链路)

完整上传链路:**校验名 → 启动上传(秒传) → 上传分片 → 合并 → 解析 → 提交创建 → (任意阶段)查状态**。

---

#### §4.2.1 Step 1 — 同租户名校验

**作用:** 校验应用名是否在当前租户已存在(避免重名),不阻塞流程(渠道可强制覆盖)。

| | |
|---|---|
| **HTTP** | `POST /open/api/vendor/v1/app/checkAppNameExists` |

#### §4.2.3 Step 3 — 上传分片(多次循环)

| `contentMd5` | string | ✓ | 当前分片 MD5 |

#####  分片重传 etag 处理(说明)

若同一 `partNumber` 重传(网络中断恢复 / 覆盖旧数据):
- **每次重传,OSS 都会返回新 etag**
- Step 4 合并时,**必须使用最新一次响应的 etag**
- 客户端建议:每次成功响应即覆盖 etag 缓存

| code | HTTP | 触发场景 | 处理建议 |
|---|---|---|---|
| `UPLOAD_SESSION_EXPIRED` | 404 | uploadId TTL 已过(24h) | 重走 Step 2 |
| `OPERATION_FAILED` | 500 | partNumber 超出 totalParts / 分片 MD5 不匹配 | 检查 partNumber 与 MD5 |

#### §4.2.7 Step 7 — 查询上传任务状态

**作用:** 在 Step 1-6 任意阶段被中断时,查询上传会话的当前状态。**用于断点续传 / 失败恢复**。

| | |

| **超时建议** | 30s |
| **调用时机** | 网络中断恢复 / 上传超时 / 客户端崩溃后恢复 |

##### 出参

`data` 是状态字符串(**不是嵌套对象**)。

##### 完整响应示例


| 值 | 含义 | 渠道下一步 |
|---|---|---|
| `OSS_UPLOADING` | 上传中(分片已开始) | 继续 §4.2.3 上传未完成的分片 |

#####  长任务边界(说明)

- uploadId 存于 Redis,**TTL 24h**
- **大文件(数 GB)跨夜上传场景容易失效**:22:00 起传 → 凌晨断网 → 第二天 09:00 续传时已超 24h
- 失效后本接口返回 `"上传任务不存在或已过期"`(当前是 message,后续可能支持新错误码 `UPLOAD_SESSION_EXPIRED`)
- **建议:** 大文件分批上传,或在 24h 内完成
- 后续可能支持 TTL 配置化延长至 72h

### §4.5 预装(创建云手机时)

**作用:** 在 §2.2 创建云手机时,通过 `appIds` 字段指定**创建完成后自动安装**的应用列表。

##### 用法

详见 [§2.2 入参组 7 — 应用预装](#22-创建云手机-核心接口)。**关键点:**

- 创建时传入 `appIds: [12345, 12346]`
- 创建完成后(`status=NORMAL`),云手机内已装这些应用
- 预装失败不影响云手机创建成功(best-effort)
- 验证已装,用 §3.7.3 查询已装应用列表

##### 与 §3.7.1 装应用的区别

| 维度 | §4.5 预装(创建时) | §3.7.1 装应用(创建后) |
|---|---|---|
| 时机 | 创建中,异步装 | 创建后,异步装 |
| 失败容忍 | best-effort,失败不阻塞 | 返回失败 cpId |
| 状态查询 | 无,只能 §3.7.3 验证 | 同样无 by-task 查询 |
| 适用场景 | 渠道标配应用预设 | 后续运营追加 |

### §4.6 常见问题

| 问题 | 排查方向 |
|---|---|
| Step 2 返回 `uploadSuccess=true` | 秒传命中,直接跳 Step 6,不要传分片 |
| 跨夜上传 24h+ 后续传失败 | uploadId 失效,重走 Step 2 |
| Step 5 解析 300s 超时 | apksig 慢,客户端超时设 300s,中台未来异步化 |
| §3.7 装机后应用没出现 | 轮询 §3.7.3 已装列表,任务级查询接口需确认 |

## §5 代理管理

### §5.1 场景速览

**业务诉求:** 自定义代理 / 购买代理 / 绑定到云手机 / 可达性检测。

**接口编排:**

```
1. 查现有代理 → /static/proxy/page  /dynamic/proxy/page  /custom/proxy/manual/page  /tiktok/proxy/page
2. (购买) → /proxy-management/static/meals → /static/stock → /purchase
2'. (自定义) → /custom/proxy/add
3. 绑定到云手机 → /cloud-phone/proxy/batch-update      (见 §3.2)
4. 可达性检测 → /proxy/batch-detect
```

### §5.2 代理查询(4 接口)

中台代理分 4 类,**每类有独立查询接口**,字段结构相似但语义不同。

## §6 仿真管理

### §6.1 场景速览

 **中台特色模式(本手册重点说明)**:

中台仿真模型 = **"仿真跟随代理"**。仿真(国家/时区/语言/GPS)不是独立维度,而是与代理绑定的配套属性。

**因此:**
- **创建时设仿真:** §2.2 创建云手机入参组 5(顶层平铺 region/timezone/sysLocale 等)
- **修改仿真:** §3.2 代理下发时,通过 `regionFollowProxy/timezoneFollowProxy/languageFollowProxy` 自动更新
- **查询仿真值:** §2.6 v2 查询返回的 `proxyInfo.country / countryName / province / city / timeZone` 等字段

### §6.2 仿真下发现状

| 时机 | 接口 | 入参字段 |
|---|---|---|
| 创建云手机时 | §2.2 `/cp/create` | `regionOption / timezoneOption / languageOption / region / timezone / sysLocale / latitudeDegrees / longitudeDegrees / networkType / operatorId` |
| 绑定代理时 | §3.2 `/cloud-phone/proxy/batch-update` | `regionFollowProxy / timezoneFollowProxy / languageFollowProxy`(自动跟随代理检测结果) |

### §6.3 查询国家 / 城市 / GPS / 时区元数据

## §7 自动化脚本任务

### §7.1 场景速览

**业务诉求:** 在云手机上调度自动化脚本(如批量养号、定时操作)。

**接口来源说明:** 本章 `/open/api/autoScript/*` 属于自动化脚本服务入口,不是 vendor-service 本地 controller。交付给渠道前需确认网关路由、AKSK 权限和目标环境已开通该服务。

**核心概念:**

- **脚本模板 (Script Template)** — 一段 Lua 脚本,定义可执行的自动化逻辑
- **Task** — 单次执行单元(在 N 台云手机上跑一次模板)
- **Plan** — 周期性调度器,按周期 / 每天定时下发 Task

 **本手册重点澄清:Plan 与 Task 的语义层级关系**

| 维度 | Plan(计划) | Task(任务) |
|---|---|---|
| 角色 | 调度器 / 触发器 | 单次执行单元 |
| 状态机 | NOT_STARTED / PAUSED / ENABLING / FINISHED | WAITING_PUBLISH / WAITING_EXECUTE / QUEUED / EXECUTING / COMPLETED / FAILED / CANCELLED |
| 生命周期 | 长期(按周期/每天触发) | 短期(单次执行完即终态) |
| 创建方式 | §7.3 `/scriptPlan/create` | §7.2 `/autoscript/task/create-scheduled` 直接建,或 Plan 周期触发自动建 |

**关系图:**
```
Plan(NOT_STARTED → ENABLING → FINISHED)
  │
  └─ 按 executionFrequency(INTERVAL/DAILY)周期下发 Task
      └─ Task(WAITING_PUBLISH → EXECUTING → COMPLETED/FAILED)
```

**作用:** 创建 N 个一次性脚本任务(每台云手机一个 task),按 `publishTime` 调度执行。**对应 Task 模型**(参 §7.1 Plan/Task 关系说明)。


#####  跨境业务时区(说明)

`publishTime` 字段**无时区**,中台按北京时间解析。**跨境场景必踩:**
- 美国客户:本地 9 AM = 北京时间 22:00 / 24:00 / 23:00(随夏令时)
- 越南 / 巴西 / 印尼:类似

**当前规避:** 客户端将本地时间转换为北京时间后再传。

后续可能支持 ISO 8601 + 显式时区支持。

#### §7.5.1 上传脚本模板  需单独确认

>  **重要说明:本节为"需确认协议"的章节占位**
> 中台后台**已实现完整的脚本模板上传功能**(管理后台显示"同步脚本 / 导入脚本"按钮,见 [渠道商管理后台截图](附录 — 脚本管理界面)),但**对外 API 当前未文档化**。这是渠道接入自动化场景时的关键缺口。

##### 当前已知信息

| 项 | 已知 |
|---|---|
| **服务来源** | `cloudphone-autoscript-service` 服务,与 §7 章节其他自动化接口同服务 |
| **后台功能** | 渠道商管理后台"自动化管理/脚本管理"页面已有"同步脚本 / 导入脚本"功能 — 截图证实 |
| **脚本格式** | Lua(.lua 文件,通常 KB-MB 级别) |
| **关联字段** | 上传成功后,模板对象包含 `id / name / scriptVersion / luaFileUrl / luaFileSize / luaFileMd5 / startParamMap`(可通过 §7.5.2 查询验证) |
| **使用场景** | 上传后通过 `id` 在 §7.2 / §7.3 创建任务时引用为 `scriptId` |

##### 需单独确认的接口规范

接口已存在,但需要中台**对外发布以下规范**才能让渠道真正接入:

| 需确认内容 | 期望 |
|---|---|
| **HTTP 路径** | 推荐 `POST /open/api/autoScript/api/automation/templates/upload` |
| **入参格式** | `multipart/form-data`:`name / description / luaFile / startParamMap / isPublic / scriptVersion` 等字段 |
| **出参字段** | 上传成功后返回的 `id / luaFileUrl / luaFileSize / luaFileMd5 / createTime` 等 |
| **权限控制** | AKSK 鉴权 + 租户隔离(只能上传到自己租户) |
| **大小上限** | 单文件大小限制(预估 ≤ 10MB) |
| **版本管理** | 同名脚本是否覆盖 是否需要 `scriptVersion` 强制递增 |
| **审核流程** | 是否需要中台审核环节后才能使用 |
| **错误码** | 文件格式错 / 大小超限 / 命名冲突 / 内容不合法 等场景的明确错误码 |

##### 渠道当前获取脚本的过渡方案

在中台正式对外文档化前,渠道可:

1. **联系中台对接人**:把 Lua 脚本通过工单 / 企微提交,中台后台**手动导入**
2. **拿到 `scriptId` 后**:通过 §7.5.2 查询验证,然后通过 §7.2 / §7.3 在任务/计划中使用
3. **版本迭代**:每次脚本更新都需要重走工单流程 — 严重拖慢自动化场景迭代速度

> 注意: **接入风险提示**:脚本上传接口未开放时,渠道脚本迭代需要通过工单或对接流程导入。高频迭代场景建议在接入评审中提前确认脚本上传、审核和版本管理方案。

### §8.7 接入推荐:统一 Poller 设计

 **本手册推荐**: 渠道侧建议建立**统一 Poller 服务**,封装上述碎片化的查询路径:

```
Poller {
  poll_vm_ready(vmIds) → /server/page (vmStatusList=["ONLINE"])
  poll_cp_ready(cpIds) → /cloud-phone/batch-query-status
  poll_proxy_bound(cpIds) → /cloud-phone/page (取 proxyInfo)
  poll_app_installed(cpId, packageName) → /cloud-phone/getInstalledApps
  poll_upload(uploadId) → /app/queryUploadStatus
  poll_task(ids) → /autoscript/task/query-by-ids
}
```

间隔统一 5-10 秒,中台 webhook 上线后可平滑切换为事件驱动。

### §10.1 场景 1 — TikTok 矩阵养号(从 0 到 100 台)

**业务诉求:** 跨境 MCN 想批量开 100 台云手机做 TikTok 养号矩阵。

**接入步骤:**

```
1. 查 TikTok 套餐 + 库存
   POST /proxy-management/tiktok/ip/list  { vendor: "IPIPGO" }
   POST /proxy-management/tiktok/stock    { vendor: "IPIPGO", customerId: 12345 }

2. 购买 100 个 TikTok 代理
   POST /proxy-management/purchase
   {
     "proxyOrderType": "TIKTOK", "proxyVendor": "IPIPGO",
     "mealId": 337, "mealTime": 720,
     "ipList": [{ "country": "US", "quantity": 100 }],
     "exclusiveBandwidth": "5"
   }
   → 拿到 100 个 proxyId

3. 上传 TikTok APK
   POST /app/checkAppNameExists { appName: "TikTok" }
   POST /app/upload/initiate-app + 分片上传(§4.2)
   POST /app/createFromUploadedFile → 拿到 appId=88888

4. 查规格库存 + 申请 VM(假设单 VM 跑 5 台,需要 20 台 VM)
   GET  /resource-group/all-spec-stocks
   POST /resource-group/apply { specId: 23, count: 20, ...}
   轮询 /server/page 等 vmStatus=ONLINE

5. 创建 100 台云手机(20 个 VM × 5 台)
   循环 20 次:
   POST /cp/create {
     "vmId": "vm-xxx", "number": 5,
     "imageId": "img-android11-prod", "planId": 23,
     ...仿真:regionOption=FOLLOW_PROXY, networkType: 1...
     "proxyMode": "CUSTOM",
     "proxyList": [{ proxyId 来自 step 2 }, ...],
     "appIds": [88888]               // 预装 TikTok
   }
   轮询 /cloud-phone/batch-query-status 等 status=NORMAL

6. 上传养号脚本(目前需中台导入,见 §7.5)→ 拿到 scriptId=88

7. 创建周期计划(每天 9 点养号)
   POST /scriptPlan/create {
     "scriptId": 88, "planName": "TK 早 8 养号",
     "executionFrequency": "DAILY", "executionTime": "09:00:00",
     "cpIdList": [...100 台 cpId...],
     "startTime": "2026-06-04T00:00:00", "endTime": "2026-12-31T23:59:59"
   }
   POST /scriptPlan/start?id={planId}
```

### §10.2 场景 2 — MCN 批量直播切片分发

**业务诉求:** MCN 把 5 GB 直播切片 APK 分发到 50 台云手机。

**接入步骤:**

```
1. 上传大 APK(分片上传 + 跨夜)
   POST /app/upload/initiate-app(注意 24h TTL,大文件分批)
   循环 § 4.2 Step 3 上传分片
   POST /files/upload/complete-new 合并
   POST /app/getAppInfoFromFile 解析(300s 超时)
   POST /app/createFromUploadedFile 拿到 appId=99999

2. 50 台云手机已经创建好,批量装应用
   POST /cloud-phone/installApp { cpIds: [50 台], appIds: [99999] }
   → 拿到 50 个 taskId,轮询 /cloud-phone/getInstalledApps 看是否装上

3. WebRTC 接管看屏
   POST /cloud-phone/webrtc-auth { cpIds: [选定的几台] }
   前端建立 WebRTC 连接,看直播
```

### §10.3 场景 3 — 跨境电商挂机 + 自动化操作

**业务诉求:** 跨境电商在 30 台云手机上挂 Shopify 客户端,定时自动刷新订单。

**接入步骤:**

```
1. 已有 30 台云手机 + Shopify 应用预装

2. 创建一次性任务,每天分钟级触发
   POST /autoscript/task/create-scheduled {
     scriptId: 88(Shopify 刷单脚本),
     taskName: "Shopify 订单刷新",
     taskList: [
       { cpId: "cp-1", publishTime: "2026-06-04T08:00:00",
         scriptParams: "{\"store\":\"shop1.com\"}" },
       ... 30 条
     ]
   }
   → 拿到 30 个 task id

3. 渠道侧 Poller 每 30 秒查询任务状态
   POST /autoscript/task/query-by-ids { ids: [30 个 id] }
   触发到 COMPLETED 后,通过 /autoscript/task/report 拿截图 + 日志

4. 失败任务自动重跑
   对 taskStatus=FAILED 的 id 调用 /autoscript/task/re-execute
```

<a id="11-常见问题-faq"></a>
## §11 常见问题 FAQ

### Q1 接入第一步该做什么

读 §0(接入前必读)→ 找中台拿 AKSK + 测试环境 + 至少一个测试 VM/镜像 → 走 §10.1 完整跑通一次。

### Q2 返回业务失败码怎么排查

(a) 先看 `code`:失败时会返回具体业务码,如 `SIGNATURE_INVALID` / `DATA_NOT_EXIST`,或通用 `FAIL`。(b) 看 `message` 是否含具体错误描述。(c) **保留 traceId 提交工单**。

### Q3 异步操作什么时候才算完成

参考 §8.1 任务状态查询路径汇总表。**没有 webhook 之前,统一靠轮询**(间隔 ≥ 5 秒)。

### Q4 跨境业务时间为什么不对

中台所有 publishTime / executionTime 字段无时区,**默认按北京时间解析**。跨境场景客户端要转。后续可能支持时区支持。

### Q5 为什么我的请求被限流

中台 OpenAPI 限流约 1000 QPS,单接口 200-500 QPS,用户级 50 QPS 突发 100。**轮询接口间隔 ≥ 5 秒**避免触发。

### Q6 父租户能看到子租户的代理密码吗

可以。中台业务规则:父租户允许查看子租户代理密码,合规边界为同企业账号体系内。

### Q7 v1 接口和 v2 接口什么区别

v1 是为已有租户保留的兼容层,字段稍有不同(如 v1 请求字段 `pageNum`,v2 用 `page`)。**新接入推荐用 v2**。v1 将在 12 个月内退役(中台规划中)。

### Q8 文档里 18 个云手机状态太多,客户端怎么处理

参考 §2.6 客户层 5 状态映射表(CREATING / RUNNING / STOPPED / FAILED / DESTROYED)。建议业务逻辑按 5 状态走,18 状态做 sub-status 辅助显示。

### Q9 为什么 §1.2 跨租户权限边界说明标注要怎么处理

这是当前版本需要调用方配合规避的权限边界。**接入时严格只传自己租户名下的 ids**,避免误用其他租户的 id;生产开放前请与中台确认租户边界防护方案。

### Q10 哪里能看接口的 changelog

当前尚未建立公开 changelog 机制。建议加入中台对接群,关注版本更新通知。

## §12 完整错误码

详见 [§0.5 错误码体系](#05-错误码体系含说明)。

补充说明:**HTTP 状态码** 表示协议层/框架层状态,业务成败以 body 中 `code` 为准:

| HTTP | 含义 |
|---|---|
| 200 | 请求已被业务层处理;业务成功或失败看 body 里 `code` |
| 400 | 请求格式错(JSON 解析失败 / 字段类型错) |
| 401 | 鉴权失败(AKSK 相关) |
| 403 | 权限不足(资源不属于该租户) |
| 404 | 资源不存在 / 路径错 |
| 422 | 参数校验失败 |
| 429 | 限流 |
| 500 | 服务端未捕获异常;业务失败仍以 body `code` 为准,通用失败为 `FAIL` |
