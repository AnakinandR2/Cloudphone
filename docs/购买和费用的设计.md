
我们先用DDD的思想，统一一下术语，涉及到以下术语：

余额：
    常规余额概念，admin可以给用户扣减或增加余额，只要写明理由，这给了运营很大的灵活性

云手机实例席位：
    可以购买的云手机实例数量，比如买10个席位，则可以创建<=10个云手机实例，席位可以单独购买，也可以批量购买，席位有到期时间，可以批量续费，也可以单独续费，不管这个席位当前是否有实例占用，都可以续费。实例会被自动分配席位，即使当前的席位到期了，实例直接“热迁移”到新的席位，保持继续使用即可，但是一旦席位到期后，没有更多可用的席位了，实例会自动停止运行，收入回收站，最长30天后被清理，无法找回。只有席位足够，才能从回收站恢复实例。

临时开机时长：
    临时开机时长无使用期限，用完为止
    用临时开机时长的手机，每天最多扣除200分钟，超过200分钟后，当天继续使用不扣除时长（按照UTC+8时区计算）
    计算规则：
        1. 开机满1分钟才算消耗1分钟，如果开机不满1分钟，则不消耗时长。但是开机前会检查是否有包月开机数或临时开机时长,没有则不允许开机
        举例： 在14:32:32开机，持续到14:33:00，还不算消耗1分钟，直到下一次我们同步开机时长，发现已经到了14:33:50秒，算消耗了1分钟，下次算消耗一分钟的，是14:34:32秒。


包月开机数：
    多台实例可轮流共享同一个包月名额，同一时间仅限一台实例使用。




一， 购买页面，顶部4个KPI卡片，分别是

余额，显示有多少余额，有一个充值按钮，点击后下方内容区域，进入充值余额的tab
    tab里面显示充值金额，预设几个选项（admin后台可配置），然后选择支付方式，确认支付。选择支付方式（不支持余额支付）的和确认支付的，要抽象为组件，我们后面还会大量用到。
    支付方式是否开启，以及排序，需要admin可配置，以下涉及到支付的地方都是这样


云手机实例席位，显示我总共有多少云手机实例数量可用，目前已经用了多少，有“购买新实例”按钮，点击后进入云手机实例数量购买的tab，还有“续费实例”按钮，点击后进入付费实例的tab，可以对已经购买的实例进行单独或多选的续费。
    购买新实例的tab:
        1. 显示购买须知：比如“云手机为固定套餐，过期后数据无法找回，请留意续费时间。
云手机需要配置 Socks5 类型代理 IP 才能使用，详见配置教程。
云手机售出后不支持退换，购买前请确认您的购买信息避免误购。”
        2. 选择购买数量，一个拉条可以选择购买多少个（admin后台配置，比如1,2,5,10,50,100,500,1k,2k,10k，并且admin可以给数量配置不同的折扣，达到一定的数量则给与这些折扣），用户也可以手动输入购买数量。
        3. 选择购买时长，一个按钮组，读取admin配置的时长类型和折扣，这里不允许手动输入。
        4. 展示一个实例计费的说明信息，这里你先自有发挥。
        5. 显示数量，折合每个实例的单价，整体价格，到期时间的订单总结
        6. 选择支付方式（支持余额支付）和确定支付，用上面余额的抽象组件。

    续费实例tab：
        1. 显示当前所有已购买尚未到期的席位ID，创建时间，到期时间，如果这个席位当前有实例坐着，还附加显示实例的信息（名称,ID ,状态），并且支持对齐选中，还有要简单的过滤器，比如过滤到期时间，搜索名称或实例标签什么的
        2. 显示数量阶梯对应的折扣体系，显示当前选中的数量，并展示当前数量对应的折扣，让用户在续费的时候也和新购一样享受数量越多折扣越大的好处
        3. 选择购买时长，同新购，复用组件
        4. 展示一个实例计费的说明信息，同新购，复用组件
        5. 显示订单总结，同新购，复用组件
        6. 选择支付方式，复用

临时开机时长：显示剩余时长，有“购买”按钮，点击后进入临时开机时长购买的tab：
    1. 展示购买须知，你根据上面的概念定义发挥。
    2. 选择时长包（admin配置），一个按钮组，读取admin配置的时长类型和折扣，或者用户手动输入时长，但是有一个最低值，最低值是admin配置的，用户不能输入低于最低值的时长。输入的值同样享有折扣。
    3. 订单总结，支付方式，确定支付。复用，不再赘述


包月开机数：
    显示总数量，当前正在使用的数量，有“购买”按钮，点击后进入包月开机数购买的tab：
        1. 显示购买须知，你根据上面的概念定义发挥。
        2. 选择购买数量，一个拉条可以选择购买多少个（admin后台配置，比如1,2,5,10,50,100,500,1k,2k,10k，并且admin可以给数量配置不同的折扣，达到一定的数量则给与这些折扣），用户也可以手动输入购买数量。
        3. 选择购买时长，一个按钮组，读取admin配置的时长类型和折扣，这里不允许手动输入。需要注意，虽然我们叫做包月开机时长，但这里选择时长不是按月，而是按天，比如7天，30天。
        4. 订单总结，支付方式，确定支付。复用，不再赘述
    还要显示一个续费按钮，点击后进入包月开机时长续费的tab：
        1. 显示当前所有已购买尚未到期的包月开机数ID，创建时间，到期时间，如果这个包月开机数当前有实例使用，还附加显示实例的信息（名称,ID ,状态），并且支持对齐选中，还有要简单的过滤器，比如过滤到期时间，搜索名称或实例标签什么的
        2. 显示数量阶梯对应的折扣体系，显示当前选中的数量，并展示当前数量对应的折扣，让用户在续费的时候也和新购一样享受数量越多折扣越大的好处
        3. 选择购买时长，同新购，复用组件
        4. 订单总结，支付方式，确定支付。复用，不再赘述

在没有选中任何购买或续费tab时，KPI的下方默认显示的是订单历史tab，显示所有已完成的订单，包括购买，续费，临时开机时长，包月开机数，每个订单有订单ID，订单时间，订单金额，订单状态（未支付（支持继续支付），已支付，已过期）

二， 费用日志页面
    我们后端是每分钟结算一次费用，结算费用明细的时候，理论上我们记录每个实例，占用的是包月开机，还是临时开机。
    但是我们在展示的时候，要展示一个聚合日志，而不是每分钟的日志，聚合按照开机状态展示，比如一台实例开了30分钟，然后关机了，我们显示开机时间-关机时间，占用的是包月开机还是临时开机，扣除了多少临时开机时长，如果一个实例还在开机中，则显示开机时间-运行中，占用的是包月开机还是临时开机，当前已经扣除了多少临时开机时长。
    再次提醒，一天超过xxx分钟后，临时开机时长会自动停止扣除，直到第二天继续扣除。

三，其他规则
    购买实例席位赠送临时开机时长，admin可以配置，每个实例席位每个月可以赠送多少数量的临时开机时长，避免出现用户买了席位，一点都开不了机的情况。新购和续费都会赠送。比如admin配置了每席位每月赠送200分钟，那么用户续费了2台，每台续费3个月，赠送200*2*3=1200分钟的赠送
