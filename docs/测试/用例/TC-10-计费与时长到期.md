# TC-10 计费与时长到期

> 覆盖：新购买模型（报价/下单/支付/履约/退款）、支付手续费与快照、支付幂等（CAS）、履约事务原子性、授权单元到期与续费叠加、席位溢出回收、开机名额与运行时用量结算、试用领取、订单/资源账本、席位赠送时长。· 关联：后端 `modules/billing/internal/*`、路由 `/api/v1/billing/*` 与 `/api/v1/admin/billing/*`；前端 my `BillingPurchaseView`/`BillingRuntimeLogView`/`BillingTrialsView` 与 admin `billing/{PricingConfigView,PaymentMethodsView,BillingOrdersView,BillingAccountsView,TrialsView}`。
> **背景**：这些域在 TC-09 仅做「原型冒烟」；后端已建成（billing 模块 Phase 1c+2），本文档将其升级为**完整验收用例**。凡 Plan A 自动化已覆盖者，在预期结果或末尾「自动化覆盖」小节标注对应测试文件（CI 已覆盖、无需重复手测）。

## 术语与口径

- **金额单位**：一律「分」（`*_cents`）；折扣用基点 bps，`DiscountBpsFull=10000`=原价无折扣，8500=8.5 折。
- **两类授权单元（`billing_license_units`）**：`seat`（席位，决定能存在多少台实例，按**月**计到期）、`boot_slot`（包月开机名额，决定能并发运行多少台，按**天**计到期）。
- **可用池口径**：`activeUnits` = `status='active' AND expire_at > now`（**读时过滤**，见「计费时间相关测法」）。
- **业务类型 `biz_type`**：`seat_new / seat_renew / boot_slot_new / boot_slot_renew / runtime_pack / recharge`（内置集合），另可由外部模块注册（如 library 套餐）。
- **支付方式 `pay_method`**：`balance / wechat / alipay`；`wechat/alipay` 当前为**桩网关**（无真实对接）→ 下单即视为到账、立即履约。
- **数量上限**：`MaxOrderQuantity=1000`（seat/boot_slot 单次下单/履约上限，超限 422）。

## 计费时间相关测法（如何测「30 天到期」而不真等）

> 授权单元到期完全由**读时过滤**判定：`activeUnits` = `status='active' AND expire_at > now`。因此测到期无需等真实时间流逝，只需操纵 `expire_at` 或注入合成 `now`。

- **接口/E2E 层（推荐，贴近 TC-12 到期 E2E 思路）**：先经 HTTP 造数（下单/领取或直接 seed）得到 active 单元（`expire_at=now+30d`），再用 `framework.DB` 直接**回拨** `billing_license_units.expire_at` 到过去/临界值，然后打 `GET /billing/overview` 或 `GET /billing/license-units` 观察可用池变化。示例（见 `apptest/billing_expiry_test.go`）：
  - 造数：`INSERT ... billing_license_units (... expire_at=now+30d, status='active')`；
  - 触发到期：`UPDATE billing_license_units SET expire_at = now-1s WHERE id = ...`（`status` 仍 active）；
  - 断言：`overview.seat.total` 相应减少 → 证明读时过滤生效。
  - 临界值测法：把 `expire_at` 分别置为 `now-1s`（已过期，排除）与 `now+1s`（未过期，计入），验证边界（`expire_at > now` 为严格大于）。
- **单元层**：给 `activeUnits(userID, kind, now)` / `markExpired(now)` 传**合成 `now`** 即可模拟任意时刻，无需回拨系统时钟（见 `license_repository_test.go`）。续费叠加同理——用「原到期 = now±Nd」的合成锚点验证「未过期从原到期叠加 / 已过期从 now 起算」（见 `fulfill_service_test.go`）。运行时封顶按 UTC+8 自然日（`utc8Day`），测跨日/封顶用合成 `windowEnd` 与开机时刻。
- **markExpired 现状**：`markExpired`（把过期 active 单元置 `expired` 并清 `current_instance_id`）已实现且有单测（`license_repository_test.go:TestMarkExpired_FlipsExpiredAndClearsInstance`），但**未挂载到任何路由或后台任务**（全仓无非测试调用方）。因此生产中过期单元的 `status` 字段不会自动翻转为 expired，「到期不可用」完全依赖读时 `expire_at>now` 过滤——手测时勿以 DB 里 `status` 是否仍为 active 判断到期，应以可用池（overview/license-units）为准。

## 关联/备注

- **环境**：默认 sqlite（`go test ./...` 无需外部库）；跨库并发幂等（MySQL/PG）行为在 sqlite 串行化下等价验证，试用限领在多写实例下需对 `(policy_id,user_id)` 加唯一约束/行锁（代码注释已标注 Phase 2 前置）。

- **金额与折扣口径**：见文首「术语与口径」；`payable = round(round(original×qtyBps)×durationBps)`，四舍五入到分。
- **跨文档引用**：本文档承接 TC-09（原型冒烟）升级为完整验收；到期 E2E 测法与 TC-12（到期 E2E，待建）思路一致——经 HTTP 造数 + `framework.DB` 回拨 `expire_at`，不真等时间。TC-02 覆盖实例生命周期（席位/开机名额消费方）、TC-08 覆盖营销站取试用/价格公开接口。
