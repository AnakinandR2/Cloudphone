## 4. Plan B（接口层全覆盖，TC-10/11/12/14）执行中发现（2026-07-03）

Plan B 用「17 个测试文件并行编写 + 逐文件对抗复核」补齐接口层用例，对抗复核（含变异测试）暴露如下问题。fix-and-record：属自身测试范围内的真实生产 bug 直接修并记此；语义/产品决策类不擅改，记为开放项。

### 4.1 生产 bug（已修）

- **TrialPolicy 无法经 API 建「停用」策略**。`billing/internal/trial_repository.go: createPolicy` = `db.Create(p)`，而 `TrialPolicy.Enabled bool` 带 `gorm:"not null;default:true"`；GORM 的 Create 会跳过带 default 标签的零值字段（`Enabled=false`），导致运营在后台传 `enabled=false` 建策略仍落库为 `true`——停用策略形同虚设（用户仍能领取）。
  - 修复：`trial_service.go: CreatePolicy` 在 `!enabled` 时对新行显式回写 `updatePolicy(id, {"enabled": false})`（复用已按 map 写入的 Update 路径，绕开零值跳过）。
  - 覆盖测试：`backend/apptest/billing_trial_admin_test.go::TestTrialClaimDisabledPolicyRejected`（TC-10-076，经 admin API 建停用策略→claim 应 422「试用已停用」；修复前该断言 FAIL）。

### 4.2 开放项（未改生产语义，待产品决策）

- **CanBoot 不做 boot_slot 并发占满准入拒绝**。`billing/internal/runtimeengine_service.go: CanBoot` 仅判断「临时时长余量>0」或「未过期 boot_slot 名额容量>0」，**不减去当前在跑实例数**（`run_sessions` 中 `power_off_at IS NULL` 的数量）。即只要持有 ≥1 个未过期 boot_slot 名额，无论已并发运行多少台，`CanBoot` 恒 `true`——不存在「名额占满后拒绝新开机」的准入门禁；boot_slot 名额只在 Settle 结算阶段起「按名额优先、超出退化为扣临时时长」的分账作用。
  - 与用例文档 TC-10-053 标题「开机名额并发上限」及 `CanBoot` doc 注释「空闲包月名额」的字面预期不符。
  - **为何不擅改**：把 boot_slot 改为硬并发门禁是产品/计费口径决策，blast radius 大（会开始拒绝当前放行的「按量付费超额开机」，可能误伤合法场景；且需同时厘清临时时长耗尽后 Settle 如何处理已开机会话）。补测任务不应单方面改动此生产语义。
  - 处置：测试 `backend/apptest/billing_overview_test.go::TestCanBootCapacityGateHTTP` 已按**真实契约**断言（两者皆无→false；有时长或有名额→true；名额被运行会话占满仍放行），真绑定、可回归。若未来决定加并发门禁，将该处断言改回 `false` 并同步用例文档。
