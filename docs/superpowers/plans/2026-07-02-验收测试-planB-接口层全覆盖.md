# Plan B 接口层全覆盖 实施计划（TC-10/11/12/14 穷尽）

> **For agentic workers:** 本计划用「一测试文件 = 一任务」的方式并行补齐 Plan B 的接口层自动化。
> 每个任务对应 `docs/测试/用例/TC-1x-*.md` 的一组用例点，落成 `backend/apptest/` 或模块 `internal/` 下的 Go 测试。
> 先完成【任务 0 共享基础设施】，其余任务消费其 helper。

**Goal:** 把 Plan B（TC-10 计费 / TC-11 素材库 / TC-12 应用管理 / TC-14 自动化）中**所有可在接口层（HTTP apptest）或单元层自动化**的用例点补齐，接口自动化覆盖率从 ~27% 提升到 ~77%。

**范围边界：**
- **纳入**：TC-10/11/12/14 的接口层可自动化点（约 150 个，含跨子系统 E2E：admin 配置→my 生效、上传→安装、下单→履约→到期）。
- **不纳入（归 Plan C）**：TC-13 www 内容站（Nuxt BFF `_api`/`_content`，TypeScript 栈 + SSR/浏览器）；各域纯 UI 交互点（表单渲染、弹窗、Badge 着色等）。这些在 TC-15 Playwright / 真机 runbook 覆盖。

**Architecture:** apptest 只经公开 HTTP API + `framework.DB` 直查断言，不 import 任何模块 internal。上传/安装链路用移植进 apptest 的 fake S3（httptest 起最小 S3 兼容端点）打通 presign→PUT→confirm→finalize→install-by-url。单元层补测（参数负向、席位配对等）放对应模块 `internal/`。

**Tech Stack:** Go + Gin + GORM（sqlite 测试库，`framework.SetupTestDB` 随机库名隔离）；testify（require/assert）；httptest fake S3。

## Global Constraints（每个任务都隐含遵守）

- `framework.DB` 是**包级变量** `*gorm.DB`（不是函数）。`framework.S3`/`framework.S3Library` 是具体 `*s3.Client`，测试用 `withFakeS3` 临时替换。
- **apptest 不能 import 任何模块 internal**（Modulith 边界，`framework/arch_test.go` 编译期强制）；只用公开门面（`billing.*`/`library.*`/`app.*`/`phone.*`/`proxy.*`）+ HTTP。单元测试放对应模块 `internal/`。
- **绝不 `CleanTable` 截断共享表**（seed 了 admin/角色/定价）。每个用例用**唯一手机号** + `t.Cleanup` 按 user_id 精确 `DELETE` 自造数据（照 `billing_pay_test.go` 写法）。
- **绝不弱化安全/正确性断言**来让测试通过。若某不变式在现有代码下无法被断言（说明是 bug），按 `fix-and-record`：**修生产代码** + 记录到 `docs/测试/安全回归覆盖审计-2026-07-02.md`（或本计划同目录的 findings 附录）。测试必须断言**具体不变式**（如越权返回 404/403 且 message 含特定文案），不允许"任何失败都通过"的空断言。
- **复用共享基础设施**（任务 0 产出，签名以 `backend/apptest/foundation_test.go` 为准）：`setupRouter`/`doJSON`/`decode`/`adminToken`/`createUser`/`registerUser`/`parseRFC3339`/`userIDByPhone`/`uploadLibraryFile`/`newFakeS3`/`withFakeS3`/精确清理 helper。**不要重复定义**——加新 helper 前先 grep `backend/apptest/*_test.go` 防重名。
- 每个新增测试文件运行 `gofmt`（LF）、`go build ./...` 通过、目标测试 `go test` PASS。
- 每个任务完成后：该文件覆盖的 TC 用例 ID 在 `docs/测试/` 对应文档里可回溯（在测试函数 doc 注释里标注覆盖的 TC-ID）。

## TC-10 计费

### 任务 1：报价矩阵 `billing_quote_test.go`
端点 `POST /api/v1/billing/quote`（`BizQuote`）。用例点：
- **TC-10-001** 席位新购报价：断言 `payable_cents`>0 与权威口径一致。
- **TC-10-002** 数量阶梯折扣：不同 `quantity` 命中不同 `qty_discount_bps`。
- **TC-10-003** 时长必须命中选项：非法 `duration_value` → 422「非法的购买时长」。
- **TC-10-004** 时长包按分钟阶梯：`biz_type=runtime_pack`+`minutes`，验证分钟单价 + `qty_discount_bps`。
- **TC-10-005** 充值无需报价：`biz_type=recharge` → 422「充值无需报价」。
- **TC-10-090/091/092** 席位新购/续费赠送时长预览 `gift_runtime_minutes`>0；boot_slot 不赠；配置关闭时为 0（与任务 6 admin 配置联动，可在此只验证默认赠送、关闭态放任务 6）。

### 任务 2：下单校验矩阵 `billing_order_validation_test.go`
端点 `POST /api/v1/billing/orders`（`CreateBizOrder`）、`POST /orders/:id/pay`。用例点：
- **TC-10-007** 续费需选单元：`seat_renew` 空 `unit_ids` → 422「请选择要续费的授权单元」。
- **TC-10-011** 充值禁用余额支付 → 422（Plan A 若已覆盖则跳过并注明）。
- **TC-10-012** 充值金额校验：`amount_cents<=0` → 422。
- **TC-10-013** 数量超上限：`quantity=1001` → 422「数量超过单次上限1000」。
- **TC-10-014** 数量下限：`quantity=0` → 422。
- **TC-10-015** 非法 biz_type / pay_method → 422。
- **TC-10-018** 余额不足失败回滚：充值不足下单 → 订单 unpaid、无席位、余额不变（`framework.DB` 三查）。

## 执行方式

1. 任务 0 已先行落地并提交（地基）。
2. 任务 1~17 用 worktree-free 的并行 author（每 agent 写一个独立新文件，不并发跑 go test）→ 每文件对抗复核（断言是否真绑定不变式：设想"守卫被移除测试还会过吗"）。
3. 整合：单次 `go build ./... && go test ./apptest/... ./modules/automation/internal/`，收集失败 → fix loop。
4. 发现的生产 bug 按 fix-and-record 处理并记档。
5. 最终整支复核 + 提交。
