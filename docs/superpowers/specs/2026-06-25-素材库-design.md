- 日期：2026-06-25

## 0. 背景与目标

素材库本质是我们提供给用户的一个**网盘**（底层 = 我们配置的 S3 对象存储）。用户上传的文件可被用作：

1. 上传到云手机时的文件源；
2. 自动化脚本的输入参数（如脚本在手机上打开 TikTok 上传作品，作品来自素材库）。

**本期边界**：只交付**素材库核心**（文件管理 + 配额 + 容量套餐）+ 一个对外的"取文件"接口 `library.OpenFile`。"推送到手机 UI""脚本参数化"作为独立后续 feature，本期只预留接口，不实现其消费侧。

**关键产品规则**：
- 每用户有配额。免费容量 **5 GiB**（admin 可配）。
- 可购买扩容套餐：admin 配置档位（如 50GB / 100GB / 500GB）或自定义档（最少起步）；档位可配折扣；可选套餐时长（以天计、不可自定义，买得越长折扣越高）。参考现有商品体系（billing）。
- **升级**（低→高容量）补差价：`费用 = 剩余天数 × (新套餐月费 − 旧套餐月费) / 30`。
- **降级**（高→低容量）：不可选时长、到期时长不变、已付费用不退。
- 套餐**过期** → 降级为免费套餐；若降级后已用容量超过限额，文件**不删除**，但在任何地方试图取回/使用任何文件时都得到提示或错误，无法使用（**超额锁定**）。
- 这些说明与配置数据像其他购买项一样，提供 admin 填写位置 + seed 数据。
- **暂不做相同文件归并/去重**：每次上传都是独一份；`md5` 字段先存不启用，留作后续。

## 1. 总体架构

- 新增后端模块 `modules/library`（前台按属主隔离，等价 `-kind user` 脚手架）；前端 `my/src/views/library/`；后台 `admin/src/views/library/`。
- 素材库**自包含**：自己的文件/文件夹/标签/订阅/用量/定价配置；只在两处依赖外部：
  - **存储**：直接用 `framework/s3`（presign 直传 + HeadObject + 删除）。
  - **支付/订单**：复用 billing 的钱包、支付方式与订单系统（见 §2）。
- 模块边界（Modulith）：`library` 可 import `billing` 公开门面；`billing` **绝不**反向依赖 `library`（用依赖反转的函数指针）。

## 2. 跨模块接缝：套餐订单并入 billing（Path 2）

套餐购买进入 billing 的统一订单/支付/流水体系，但 billing **不感知 library 任何业务细节**。

### 2.1 billing 侧改造（仅在 `modules/billing`）

1. **订单项加不透明载荷列**：`billing_biz_order_items` 增 `meta_json text`（billing 不解析，存各业务类型自己的载荷）。
2. **请求加可扩展参数**：`BizQuoteRequest` / `BizOrderCreate` 增 `Params json.RawMessage`（承载 library 套餐参数：`{action, tier_code, days}` 等）。
3. **业务类型注册表 + 公开门面**：
   ```go
   // billing 公开门面（modules/billing/billing.go）
   type BizQuoteResult struct {
       TotalCents int64
       MetaJSON   []byte // 存入订单项 meta_json
   }
   type BizQuoteFunc   func(userID int, params []byte) (BizQuoteResult, error)
   type BizFulfillFunc func(userID int, orderID uint, metaJSON []byte) error
   // 注册外部业务类型（library 装配时调用）。billing 仅持有函数指针，无对 library 的编译期依赖。
   func RegisterBizType(bizType string, quote BizQuoteFunc, fulfill BizFulfillFunc)
   ```
   `validBizTypes` = 内置集合 ∪ 已注册集合。
4. **委托**：`Quote`（签名增 `userID`）、`CreateOrder`、`fulfillOrder` 对**已注册类型**调用对应 `quote/fulfill`，内置类型走原 switch 不变。
   - `CreateOrder` 对已注册类型：调 `quote(userID, params)` 得权威价 + `meta_json` → 建 `BizOrder{biz_type, total}` + `BizOrderItem{target_kind=bizType, amount=total, meta_json}` → 入库 → 支付 → 履约时调 `fulfill(userID, orderID, metaJSON)`。
   - `pay` 对已注册类型：余额支付正常走 `wallet.Charge`；`total=0`（降级）时跳过扣款；第三方支付沿用现有桩。
5. **订单列表/admin 订单**：天然纳入 `lib_*` 订单；列表可选加 `biz_type` 过滤参数（便于前端只看素材库订单）。

> 不破坏现有内置类型行为；只新增"已注册类型"分支与一列、一个参数字段。

### 2.2 library 侧实现并注册（`modules/library`）

- 装配时注册四种业务类型：`lib_new` / `lib_upgrade` / `lib_renew` / `lib_downgrade`。
- `quote` 用 library 定价配置 + 当前订阅算**服务端权威价**并产出 `meta_json`。
- `fulfill` 在支付成功后更新 library 订阅 + 写资源流水（可选）。
- `params` 形状：`{ "action": "new|upgrade|renew|downgrade", "tier_code": "t100", "capacity_gb": 100, "days": 90 }`（自定义档带 `capacity_gb`，预设档带 `tier_code`；`upgrade/downgrade` 不带 `days`）。
- `meta_json` 形状：`{ action, tier_code, capacity_bytes, days, monthly_price_cents, prev_tier_code, prev_monthly_price_cents, new_expire_at }`。

## 3. 数据模型（`library/internal`）

所有表用 `library_` 前缀；建表与 seed 走 `framework.RegisterSetup`（幂等：AutoMigrate 补列、seed 先查后插）。

### 3.1 文件与组织

- `library_files`
  - `id, user_id(index), folder_id(index, 0=根), name, ext, mime_type, file_type(image|video|audio|document|other), size_bytes, s3_key(uniqueIndex), status(uploading|active|deleted), md5(index，存但不去重), created_at, updated_at, deleted_at(软删)`
- `library_folders`
  - `id, user_id(index), parent_id(0=根), name, created_at, updated_at`（递归树）
- `library_tags`
  - `id, user_id(index), name, color, created_at`
- `library_file_tags`
  - `file_id(index), tag_id(index)`（多对多；唯一约束 file_id+tag_id）

### 3.2 配额与套餐

- `library_subscriptions`（每用户一行 = 当前生效套餐）
  - `user_id(PK), tier_code(free 或档位码), capacity_bytes, monthly_price_cents(基准价快照，供升级补差价), expire_at(*time.Time，免费=nil 永不过期), status, updated_at`
  - 免费态：无行或 `tier_code=free, capacity_bytes=free_quota_bytes, expire_at=nil`。
- `library_usage`（每用户一行，配额快读副本）
  - `user_id(PK), used_bytes, updated_at`；真相可由 `sum(active files.size_bytes)` 重算（提供 reconcile）。

### 3.3 套餐订单

复用 billing 订单（§2）。`biz_type ∈ {lib_new, lib_upgrade, lib_renew, lib_downgrade}`，载荷在 `billing_biz_order_items.meta_json`。

### 3.4 定价配置 `library_pricing_config`（admin 单行 JSON，id=1，启动幂等 seed）

GORM 行（结构化字段以 JSON 序列化进 text 列，参考 billing 的 `PricingConfig`）：

```go
type LibraryPricingConfig struct {
    ID             uint      // 固定 1
    FreeQuotaBytes int64     // 默认 5 GiB
    TiersJSON      string    // []TierCfg
    CustomTierJSON string    // CustomTierCfg
    DurationsJSON  string    // []DurationOptCfg（复用 billing 同形）
    Notice         string
    BillingNote    string
    UpdatedAt      time.Time
}
type TierCfg struct {
    Code            string // 如 t50 / t100 / t500
    Name            string
    CapacityGB      int
    MonthlyPriceCents int64
    TierDiscountBps int    // 10000=原价
    Enabled         bool
    Sort            int
}
type CustomTierCfg struct {
    Enabled              bool
    MinCapacityGB        int
    PricePerGBMonthCents int64
    TierDiscountBps      int
}
type DurationOptCfg struct { // 与 billing 同形
    Days        int
    DiscountBps int
}
```

**容量单位**：`1 GB = 1024^3 字节`（GiB）。`capacity_bytes = capacity_gb × 1024^3`。

## 4. 定价与购买流程

### 4.1 计价公式（library `quote`，服务端权威）

- 标准价（new / renew）：`总价 = round( monthly × (days/30) × tierDiscountBps/10000 × durationDiscountBps/10000 )`，单位分，四舍五入。
- 自定义档月价：`monthly = capacity_gb × price_per_gb_month_cents`，再走标准价公式（套用 `custom_tier.tier_discount_bps`）。
- 升级补差价（upgrade）：`总价 = round( remaining_days × (new_monthly − old_monthly) / 30 )`。**用原始月价、不叠折扣**（严格按需求公式）。
- 降级（downgrade）：`总价 = 0`。
- `remaining_days = ceil((expire_at − now) / 24h)`（到期当天仍算 1 天；`expire_at ≤ now` 视为 0，但过期会被 cron 降级，理论上不出现）。

### 4.2 四种动作（购买时按"选中档位月价 vs 当前订阅月价"自动判定）

| 动作 | 触发条件 | 价格 | 容量 | 到期 | 月价快照 |
|---|---|---|---|---|---|
| `lib_new` | 当前为免费态 | 标准价（选档位+时长） | 立即升到档位容量 | `now + days` | = 新档位月价 |
| `lib_renew` | 选中档位 == 当前档位 | 标准价（选时长） | 不变 | `max(now, 当前到期) + days` | 不变 |
| `lib_upgrade` | 选中月价 > 当前月价 | 补差价公式 | 立即升到新档位容量 | **不变** | 更新为新档位月价 |
| `lib_downgrade` | 选中月价 < 当前月价 | 0（不可选时长、不退款） | 立即降到新档位容量 | **不变** | 更新为新档位月价 |

- `renew/upgrade/downgrade` 要求当前有未过期付费订阅；免费态只能 `lib_new`。
- 升级/降级**不可选时长**（前端禁用时长选择）。
- 降级后若 `used_bytes > 新 capacity_bytes` → 进入超额锁定（§6）。

### 4.3 过期 → 降级免费（每日 cron）

library 模块 `OnStart` 启动每日定时任务：扫描 `expire_at < now 且 tier_code != free` 的订阅 → 重置为免费（`tier_code=free, capacity_bytes=free_quota_bytes, expire_at=nil, monthly_price_cents=0`）。若此时 `used_bytes > free_quota_bytes` → 自然进入超额锁定。

## 5. 上传（Presigned 直传 S3，两段式 + 配额预占）

1. `POST /library/upload/presign` `{name, size_bytes, mime, folder_id}`
   - **配额校验**：`已用(active) + 在传(status=uploading 的声明 size_bytes 之和) + 本次 size_bytes ≤ capacity_bytes`，否则 422「容量不足，请扩容」。
   - 校验文件夹归属；生成唯一 `s3_key`（如 `library/{user_id}/{uuid}{ext}`）；建 `library_files` 行 `status=uploading, size_bytes=声明值`；返回 `presigned PUT URL`（含过期）+ `file_id`。
2. 浏览器用该 URL 直传 S3（PUT）。
3. `POST /library/upload/confirm` `{file_id, tag_ids?}`
   - S3 `HeadObject` 校验对象存在 + 读**真实大小**；用真实大小修正 `size_bytes`；置 `status=active`；累加 `used_bytes`（真实大小）；绑定标签。
   - 若 HeadObject 失败 → 删行 + 提示重传。
4. **残留清理**（cron）：`status=uploading` 且超过 N 小时（如 24h）未确认 → 删 S3 对象（若存在）+ 删行，释放预占。

> 配额"预占" = 把 `uploading` 行的声明大小计入占用（无需单独计数器），天然防并发超卖。

## 6. 配额与超额锁定（核心规则）

**锁定条件**：`used_bytes > capacity_bytes`（仅由降级或过期降级造成；纯免费用户因上传被拦在限额内，不会触发）。

| 操作 | 锁定时行为 |
|---|---|
| 列表 / 查看文件元信息 | ✅ 正常（看得见才能删） |
| 删除文件、删文件夹、改名、移动 | ✅ 允许（删除是降回容量内的唯一出路） |
| 新上传（presign） | ❌ 拒绝（容量不足本就拦截） |
| **取回/使用任何文件**：下载、presigned GET、`library.OpenFile`、未来推手机/脚本引用 | ❌ 报错「容量超限，请扩容或删除文件后再使用」 |

`used_bytes ≤ capacity_bytes` 后访问自动恢复。锁定判断集中在一个 `assertNotLocked(userID)` 帮助函数，下载与 `OpenFile` 都调它。

## 8. 后端 API

前台（`user.AuthMiddleware()`，按属主隔离），前缀 `/api/v1/user`：

- 文件：
  - `POST /library/upload/presign`、`POST /library/upload/confirm`
  - `GET /library/files`（参数：folder_id、file_type、tag_id、keyword、page、size）

- `GET /admin/library/pricing`、`PUT /admin/library/pricing`

## 10. Seed 数据（`library_pricing_config` id=1）

- `free_quota_bytes` = `5 × 1024^3`（5 GiB）
- `tiers`：
  - `t50`：50GB，月价 1000 分（¥10），折扣 10000，启用，sort 1
  - `t100`：100GB，月价 1800 分（¥18），折扣 10000，启用，sort 2
  - `t500`：500GB，月价 8000 分（¥80），折扣 10000，启用，sort 3
- `custom_tier`：启用，起步 50GB，每 GiB 月价 20 分（¥0.2/GB/月），折扣 10000
- `duration_options`：`30天(10000) / 90天(9500) / 180天(9000) / 365天(8000)`
- `notice` / `billing_note`：默认文案（含"套餐过期降级为免费、超额后文件只可查看/删除不可取用""文件暂不去重"提示）
