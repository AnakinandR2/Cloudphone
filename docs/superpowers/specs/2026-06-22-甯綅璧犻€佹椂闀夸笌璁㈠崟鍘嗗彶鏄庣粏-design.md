# 席位购买赠送临时时长 + 订单历史明细与过滤 · 设计文档

- 日期：2026-06-22
- 范围：`backend/modules/billing`（增量）+ `my/`（订单历史页）+ `admin/`（临时时长配置页）
- 状态：已通过脑暴评审，待写实现计划
- 上游需求：[docs/购买和费用的设计.md](../../购买和费用的设计.md) 第「三」节 + 第「一」节订单历史
- 依赖基线：[2026-06-21-购买与费用重构-design.md](./2026-06-21-购买与费用重构-design.md)（本设计在其已落地的新模型上增量）

## 0. 背景与目标

在已重构的「一个钱包 + 三种可购买资源」模型之上，新增两件事：

1. **席位购买/续费赠送临时开机时长**：避免「用户买了席位却一点都开不了机」。admin 配置「每席位每月赠送多少分钟」，新购与续费都赠送。
2. **订单历史增强**：在 `my` 订单历史里展示每单的明细（买了多少个、多长时间），并支持按时间区间与状态过滤。

**已确认决策**：

| 决策点 | 结论 |
|--------|------|
| 赠送触发范围 | **仅实例席位**（`seat_new` / `seat_renew`）；包月开机数本就能开机，不赠送 |
| 赠送公式 | `每席位每月分钟数 × 席位数量 × 月数`（席位时长单位恒为「月」，整月、无小数） |
| 赠送配置位置 | admin **临时时长 RuntimeConfig** 页（赠送物是 runtime minute，与单价/封顶同处） |
| 赠送原子性 | 与订单履约在同一 DB 事务内入账 |
| 订单历史明细展示 | **每行摘要 + 可展开详情**；列表接口随单返回 `items`，一次加载 |
| 时间过滤 | 服务端 `created_at` 区间过滤（与分页、状态过滤一致放服务端） |

## 1. 功能一：席位赠送临时开机时长

### 1.1 Admin 配置

`RuntimePackCfg`（[pricingconfig_model.go](../../../backend/modules/billing/internal/pricingconfig_model.go)）新增字段：

```go
GiftMinutesPerSeatMonth int // 每席位每月赠送的临时开机分钟数；0 = 关闭赠送
```

- 默认 `0`（关闭）；在 `defaultPricingConfig()` 补默认值。
- JSON 编解码沿用现有泛型 marshal，无需改 repository 逻辑。
- admin **临时时长 RuntimeConfig** 页（`admin/src/views/billing/...RuntimeConfig`）新增一个输入项，`SavePartial` 仅更新该计价字段（与现有透传 notice 的 partial 保存一致）。
- 用户侧：席位「购买须知」只读回显该赠送规则（让用户在下单前看到福利）。

### 1.2 履约入账（后端核心）

在 `fulfillOrder`（[bizorder_service.go](../../../backend/modules/billing/internal/bizorder_service.go)）对 `seat_new` / `seat_renew` 分支，在调用完 `FulfillNew` / `FulfillRenew` 之后、同一事务内追加赠送：

```
gift = cfg.GiftMinutesPerSeatMonth × seatQty × months
  其中：
    新购   seatQty = item.Quantity            months = item.DurationValue
    续费   seatQty = len(renewUnitIDs)         months = item.DurationValue
```

- `gift > 0` 时调用现有 `rtWallet.addMinutes(userID, gift)` 加余量，并写一条 `LedgerEntry`：
  - `subject = runtime_minute`
  - `type = gift`（**新增账目类型**，区别于 `purchase`/`trial`/`adjust_grant`，便于对账与报表）
  - `delta = gift`，`reason = "席位购买赠送"`，`ref_type/ref_id` 指向该订单
- `cfg.GiftMinutesPerSeatMonth == 0` → 完全跳过，不写账。
- 赠送的分钟数即普通临时时长：开机时按「包月优先、临时回落」正常消耗，受每台每天封顶约束，无特殊逻辑。

### 1.3 赠送的可见性

- **报价预览**：`POST /billing/quote`（[billing2_api.go](../../../backend/modules/billing/internal/billing2_api.go)）对 seat 新购/续费在响应里增加 `gift_runtime_minutes`（= 按当前数量/时长算出的赠送量）。`OrderSummary.vue` 展示「赠送 X 分钟临时开机时长」。
- **订单留痕**：`BizOrder`（[bizorder_model.go](../../../backend/modules/billing/internal/bizorder_model.go)）新增列 `GiftRuntimeMinutes int`（履约时写入实际赠送量），供订单历史直接展示「赠 1200 分钟」。
  - 取舍：相比「从 ledger 反查赠送」，订单列更直观、查询更简单，且赠送量与订单一对一，落在订单上语义自洽。

## 2. 功能二：订单历史明细与过滤

### 2.1 后端：列表随单返回明细 + 时间过滤

`ListBizOrders`（`GET /billing/orders`，[billing2_api.go](../../../backend/modules/billing/internal/billing2_api.go)）：

- **明细随单返回**：在 `listOwned` 取到本页订单后，用本页订单 ID 一次性批量查 `billing_biz_order_items`，按 `order_id` 分组挂到各订单。响应每个订单形如 `Order2 + { items: OrderItem2[], gift_runtime_minutes }`。
- **新增过滤参数**：`from` / `to`（`created_at` 区间，ISO 日期/时间），与现有 `status`、`page`、`size` 并列。在 `bizorder_repository.go` 的 `listOwned` 增加 `created_at >= from AND created_at <= to` 的可选 WHERE。

### 2.2 前端：过滤栏 + 摘要列 + 展开详情

[OrderHistoryPanel.vue](../../../my/src/views/billing/purchase/OrderHistoryPanel.vue)：

- **过滤栏**：日期区间选择器 + 状态下拉（all/unpaid/paid/expired），均联动服务端参数；任一过滤变化时 `page` 重置为 1 重新拉取。（移除/替换原本未联动后端的客户端搜索框。）
- **明细摘要列**：由 `items` 派生一行摘要字符串：
  - `seat` → `实例席位 ×{qty} · {months}个月`
  - `boot_slot` → `包月开机数 ×{qty} · {days}天`
  - `runtime_minute` → `临时时长 ×{quantity}分钟`
  - `balance`（充值）→ `充值 ¥{amount}`
  - 末尾若 `gift_runtime_minutes > 0` 追加 `· 赠{gift}分钟`
  - 多 item 订单：摘要列出各 item，以 `；` 分隔。
- **可展开详情**：点击行展开，渲染完整 items 表（target_kind、数量、时长+单位、折前单价、数量折扣、时长折扣、金额），数据来自列表已加载的 `items`，**不再二次请求**。若有赠送，附一行「赠送临时开机时长：X 分钟」。
- **类型/i18n**：`my/src/types/billing.ts` 的 `Order2` 增加 `items?: OrderItem2[]` 与 `gift_runtime_minutes?: number`（`OrderItem2` 已存在，无需新增）；`my/.../locales/{en,zh-CN}.ts` 增加摘要标签、过滤栏、赠送等文案键。

## 3. 数据迁移

无生产数据，AutoMigrate 直接生效：

- `BizOrder` 增列 `gift_runtime_minutes int default 0`。
- `LedgerEntry` 的 `type` 增加取值 `gift`（字符串枚举，无 schema 变更）。
- `RuntimePackCfg` 增字段 `GiftMinutesPerSeatMonth`（JSON 列，无 schema 变更）。

| 层 | 文件 | 改动 |

## 5. 非目标（YAGNI）

- 包月开机数/充值订单的赠送（仅席位赠送）。
- 赠送的退款/撤销（系统本无退款链路）。
- 已购席位的「追溯补赠」（仅对新发生的购买/续费生效）。
- 订单历史的导出/复杂报表（仅时间区间 + 状态过滤）。
