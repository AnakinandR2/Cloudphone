## 1. 目标

1. 验证候选版本全部已建功能的**功能正确性**与端到端可用性（三端 admin/my/www + 后端全部模块）。
2. 验证**资金安全**：支付/履约/结算/试用的原子性与幂等（重复回调不重复扣款、扣款失败整单回滚、时长结算不重复扣）。
3. 验证**身份与权限隔离**：前台 user ↔ 后台 staff 令牌不通用；属主隔离（BOLA/IDOR）；RBAC 提权边界（非超管无法提权自己/他人）。
4. 验证**云手机生命周期状态机**与席位/开机数池的收敛、门禁一致性。
5. 验证与外部**云手机中台**对接链路的契约一致性（契约/降级为主，受控真机联调兜底）。
6. **回归防潮**：上一轮 code-review 修复的严重/高危缺陷固化为常驻回归用例，防止回退。

## 4. 接口层优先的跨子系统 E2E 策略 ★核心原则

**判据（写死，避免以后扯皮）**：
> 一条链路能否只用 **HTTP 请求 + DB 断言** 复现？
> **能 → 接口层（L2）**；必须看渲染结果/浏览器行为 → Playwright（L3）；必须真机/人眼 → 人工（L4）。

**为什么可行**：`backend/apptest` 打的是**真实路由**，而真实路由**同时挂载 staff（后台/admin）与 user（前台/my）两个身份域**。同一个集成测试里即可"用 admin 令牌配置 → 换 user 令牌验证生效"，天然覆盖跨子系统端到端，且不起浏览器、可重复、零 token。现有 apptest 已是此套路（`adminToken` + `registerUser` 并存）。这些链路多为纯内部逻辑，即使碰中台也走降级适配层。

**接口层做全的跨子系统链路清单**：

| # | 链路 | admin/staff 动作 | my/user 断言 | 碰中台 |
|---|---|---|---|---|
| X1 | RBAC 即时生效 | 改某员工角色/权限 | 该 staff 令牌访问对应接口放行/拦截随之变（token_version 递增旧令牌立即失效） | 否 |
| X2 | 禁用前台用户 | `/api/v1/admin/users` 禁用 | 该用户旧令牌立即 401（bumpTokenVersion，回归 A4） | 否 |
| X3 | 定价+手续费 | 配 pricingconfig / 手续费分档 | my 下单接口读到的价格、手续费、满额免阈值一致 | 否 |
| X4 | 试用/套餐 | 配 trial 多资源 | user 领取 → license 单元数量/到期正确；重复领受唯一约束保护（回归 B5） | 否 |
| X5 | 代理推荐 | 配 partner proxy 推荐 | my 看到推荐代理 | 否 |
| X6 | 应用市场 + Store 隔离 | 上架应用到 store | my 市场可见/可装；跨 store 拿不到 | 降级 |
| X7 | 素材去重 + 私有桶 | 用户 A 上传素材 | 用户 B 同内容命中全局去重复用；B 拿不到 A 的私有素材（属主隔离） | 降级 |
| X8 | 自动化参数注入 | 配脚本参数 | 下发任务时 `scriptParams` 按**嵌套 console 格式**正确注入（`${}` 替换只认该格式） | 降级 |
| X9 | 计费到期全链路 | （user）下单 → seed `expire_at` → 触发 reconcile | 席位池/可建机数变化 + 溢出实例回收 | 否 |
| X10 | 席位计费越权（I1） | — | user 改 `status` 绕过席位计费被拒（status 非前台可写字段） | 否 |
| X11 | 代理绑定属主校验（I2） | — | Create/Update 绑他人或悬空 `proxy_id` 被拒 | 否 |

**Playwright（L3）收窄到仅**：www SSR 首屏登录态 / Cookie 同意 / i18n / 主题切换；Vue 组件级表单实时校验、状态轮询、弹窗；购买面板数量上限（前端 = 后端 `MaxOrderQuantity=1000`）；WebRTC 远控真实推流归 L4。

## 5. 安全回归矩阵 ★固化上轮 code-review 战果

来源：`docs/code-review-2026-07-02.md`。**严重(5)+高(9) 全部转为常驻回归用例**（P0/P1）；**中危(18) 挑"可回归、有价值"补**；低危不强求。每条 = 一条可判定的回归断言，防回潮。

### 5.1 严重 + 高（必做，卡准出）

| 编号 | 缺陷 | 回归断言 | 层 |
|---|---|---|---|
| S1 | 低权账号铸造高权角色并自赋 | 非超管创建/更新角色，`permissions` 超出自身权限集 → 403 | L2+L5 |
| A1 | `staff:edit` 把任意用户置 `is_superuser` | 非超管更新自己/他人 `is_superuser:true` → 落库仍 false | L2+L5 |
| A2 | `staff:create` 直接造超管 | 非超管创建携 `is_superuser:true` → 新用户 false | L2+L5 |
| A3 | `role_ids` 绑任意高权角色 | 非超管给用户赋含越权权限的角色 → 403 | L2+L5 |
| A4 | 禁用员工不失效令牌 | `is_active` true→false 后旧令牌立即 401（token_version 递增） | L2 |
| B1 | 订单支付并发重复扣款+重复履约 | 并发/重复支付回调 → 只扣一次、只履约一次（CAS 状态守卫） | L2 |
| B2 | `MarkPaid` 非幂等重复发放 | 重复回调 → 幂等，不重复发放 | L2 |
| B3 | 余额支付扣款成功履约失败丢货 | 履约失败 → 整单事务回滚，余额不减 | L2 |
| F1 | 调度器 goroutine 无 recover 击穿进程 | 后台任务单次 panic 被 recover，进程存活 | L1 |
| F2 | 弱默认 `JWT_SECRET` 仅告警 | 生产模式弱/空密钥 → fail-fast 启动失败 | L1 |
| I1 | 前台 mass-assignment 写 `status` 绕过席位计费 | user 提交 `status` → 被忽略/拒绝 | L2+L5 |
| O3 | APK/XAPK 压缩炸弹 OOM | 超大小上限的包 → 解析被拒，内存不爆 | L1 |
| C1 | 单台启停/杀应用丢失中台失败列表 | 中台返回部分失败 → 如实回报失败列表 | L2 |
| S2 | 代理探测 = SSRF/内网端口探测 | `POST /api/v1/proxy/probe` 传内网/环回地址 → 被拦截 | L2+L5 |

### 5.2 中危（挑可回归高价值项补，P1/P2）

| 编号 | 缺陷 | 回归断言 | 层 |
|---|---|---|---|
| A5 | 可删超管/自身/末位超管 | 非超管删超管、任意人自删、删末位超管 → 拒 | L2 |
| I2 | 绑他人/悬空 `proxy_id`（BOLA） | 见 X11 | L2 |
| B4 | HA 下 `Settle` 重复扣临时时长 | `(session,window)` 唯一约束 + 条件写，重复结算不重复扣 | L2 |
| B5 | 试用 COUNT-then-INSERT 超领 | 唯一索引保护，见 X4 | L2 |
| B6 | 充值金额无上限可溢出 | 超上限充值 → 拒 | L2 |
| S3 | CORS 反射任意 Origin + 凭证 | 未配置 `CORS_ALLOWED_ORIGINS` → 不回显任意 Origin、不发凭证 | L2+L5 |
| S4 | 列表 `size` 不钳制拉全表 | `?page=0&size=-1` → 钳制，不 `Limit(-1)` | L2 |
| O6 | 明文密钥落访问日志 | 开 `ACCESS_LOG_USER_ENABLED` 后 `fullKey/token` 被脱敏 | L2 |
| C2/C5/C6 | 中台失败静默/OOM/无差集回报 | 分批+差集回报、大素材不 OOM、按 URL 安装有回报 | L2 |

## 6. 计费与"时间相关"测法专章 ★

**核心原则：到期靠数据 + `now` 参数驱动，绝不真等。** 依据（已核对实现）：
- 到期是存库时间戳 `LicenseUnit.ExpireAt`（[license_model.go:19](../../../backend/modules/billing/internal/license_model.go#L19)）；
- `activeUnits(uid,kind,now)` / `markExpired(now)` **把 `now` 当参数收**（[license_repository.go:39](../../../backend/modules/billing/internal/license_repository.go#L39)、L99）；
- 席位分配核心 `planSeatAssignment` **不依赖 DB/时钟**（[license_reconcile.go:39](../../../backend/modules/billing/internal/license_reconcile.go#L39)）；
- **无到期定时器**：billing `OnStart/OnStop` 为空（[module.go:92](../../../backend/modules/billing/internal/module.go#L92)）。到期靠**读时过滤**（`activeUnits` 只返回未过期）+ **动作触发的 `markExpired`/`ReconcileSeats`**。

### 6.1 三种时间注入手段（按层级取用）

1. **传未来的 `now`**（L1 单元/仓储）：直接给 `activeUnits`/`markExpired` 喂"30 天后"的时间点断言到期/回收。最快、无副作用。
2. **改 `expire_at` seed 边界**（L2 接口/E2E）：正常下单拿到 license 行后，把库里 `expire_at` 直接 UPDATE 成过去/临界值，再打接口并**触发那条会调 `markExpired`/`ReconcileSeats` 的动作路径**，验证到期失效、席位溢出回收、续费叠加。
3. **纯逻辑喂构造数据**（L1）：`planSeatAssignment` 直接喂 `seatRef`/`instanceRef`，断言配对与溢出回收顺序（到期倒序热迁移稳定）。

### 6.2 场景清单（每条给测法 + 层）

| 场景 | 测法 | 层 |
|---|---|---|
| 到期前可用 | 传 `now < expire_at`，`activeUnits` 返回该单元 | L1 |
| 30 天到期即失效 | 传 `now > expire_at`（或改 `expire_at` 过去）→ 不再计入可用池 | L1/L2 |
| **续费从原到期叠加**（非从当下） | `extendExpiry` 的 `addFrom(cur)` 从 `u.ExpireAt` 起算，断言新到期 = 原到期 + 周期 | L1/L2 |
| 永久单元 | `ExpireDays=0` → 到期 = now + 100 年，长期可用 | L1 |
| 试用到期 | 领取后 seed `expire_at` 过去 → 失效；重复领受唯一约束（B5） | L2 |
| 席位溢出回收 + 热迁移 | 席位数 < 实例数 → 最新创建实例进回收；席位按到期倒序分配 | L1 |
| 包月开机数并发上限 | boot_slot 池满 → 再开机被门禁拒 | L2 |
| 运行时计量结算 | 造 session 窗口 → `Settle` 结算；重复结算不重复扣（B4） | L2 |
| 支付手续费分档/满额免 | 配分档 → 不同金额下单断言手续费与满额免阈值 | L2 |
| 支付 CAS 重复回调 | 见安全矩阵 B1/B2 | L2 |

### 6.3 是否需要 clock seam（可选，YAGNI）
默认**不加**注入式时钟——上述数据 seed + 传 `now` 已覆盖验收。仅当未来引入"真·到期 cron"且要端到端驱动其推进时，再评估在 worker 边界加一个 `clock` provider。本期不做。

## 7. 人工 / 受控真机联调（L4）

**前提**：有受控联调环境（`backend/.env` 配 AKSK，可连真实中台）。**成本控制：真机测后立即销毁。**

**真机联调 runbook（最小集，上线前最后把关）**：
1. user 下单/领试用 → 建机（真机）→ 校验中台创建成功、本地状态收敛。
2. 远控接入（WebRTC 推流可见可控）→ 截屏/音量/旋转/摇一摇。
3. 素材库选文件推送 → 目标机可见。
4. 按 URL / 应用市场安装应用 → 安装结果如实回报（回归 C1/C6）。
5. 群控：多台批量启停/杀应用 → 部分失败如实回报失败列表（回归 C1）。
6. **销毁实例**（务必执行）→ 校验席位释放、reconcile 收敛。

**其余人工项**：www 三端视觉/UX/响应式、i18n 中英切换、主题色 SSR 首屏、Cookie 同意。

## 8. 测试数据隔离约定（apptest）

已核对 [testutil.go:22](../../../backend/framework/testutil.go#L22)：`SetupTestDB(m *testing.M)` **已按包创建随机后缀隔离库**（sqlite `test_<8位>.db`），跑完 `Teardown` 删除。粒度是**每测试包一库**（`TestMain` 调一次），非每函数。

- **做法 A（默认，主用）**：跨子系统 E2E 留在 `apptest`，**唯一命名 + 自己清自己造的数据**，**绝不 `CleanTable` 截断共享表**（seed 了 admin/角色，backend/CLAUDE.md 明确）。适用属主隔离型数据（按唯一 user 键）。
- **做法 B（补充）**：会改**全局可变配置**的链路（定价 X3 / 手续费 / RBAC 权限 X1 / 试用配置 X4），单拉 **`apptest/e2e` 独立测试包（自带 `TestMain`）** 拿独立随机库，避免污染其他测试，且可安全 `t.Parallel()`。
- **不用做法 C**（每函数一库）：与全局 `framework.DB` + 各模块 `Init(db)` 只装配一次的设计对着干，代价高。
- 同包测试 Go 默认**串行**，"先设置再断言"对全局配置安全；仅并行或强隔离时才走做法 B。
