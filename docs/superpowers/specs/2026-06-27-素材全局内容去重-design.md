# 素材/应用 全局内容去重（blob + 引用计数 + 秒传） — 设计

- 日期：2026-06-27
- 范围：私有素材库桶（`framework.S3Library`）内的所有内容——用户文件 + 用户应用（应用即 `file_type=app` 的库文件，天然覆盖）。相同内容（`md5` 且 `size_bytes` 相同）全库只存一份物理对象，逻辑文件以引用方式共享；最后一个引用删除时才真正删除 S3 对象。
- 反转早前「不去重」的决定。

## 1. 目标与非目标

### 目标
1. **全局去重**：跨所有用户，相同 `(md5, size_bytes)` 在 S3 只存一份物理对象。
2. **引用计数**：多个逻辑文件指向同一物理对象；删除只减引用，引用归零才删 S3。
3. **秒传（跨用户，百度网盘式）**：上传前以 `(md5, size, slice_md5)` 查重命中即跳过上传，瞬时建立引用。
4. 配额语义不变；仅新上传生效（不迁移存量）。

### 非目标（YAGNI）
- 应用市场 / 图标（公有桶 `framework.S3`）不在本次范围。
- 存量旧文件回填/合并（它们无 md5）——仅新上传去重。
- 配额随去重变化（每个逻辑文件仍按自身大小计入配额）。

## 2. 安全：跨用户秒传与残留风险（已决策）

经典「按 md5 秒传」在全局去重 + 私有内容下的风险：用户只声称某 `md5`（他人私有文件）而不实际持有，即可秒传拿到指向他人内容的链接 → 越权下载。

**采用百度网盘式防护**：秒传凭证 = `md5 + size_bytes + slice_md5`，其中 `slice_md5 = md5(文件前 256KB)`。
- 命中条件：已有 blob 的 `(md5, size_bytes)` 匹配 **且** `slice_md5` 与该 blob 记录的一致 → 秒传。
- 效果：仅知道一个 md5 字符串不足以秒传——必须持有文件**前 256KB** 才能算出 `slice_md5`，等价于实质持有该内容，堵住最廉价的纯 md5 声明攻击。
- **残留风险（如实记录、用户已接受）**：若攻击者确掌握某文件前 256KB + md5 + size，仍可秒传该文件。这是「百度网盘式」固有、可接受的剩余面。
- 不论秒传与否，所有**真实上传**在 confirm 阶段一律服务端用 S3 ETag 权威校验 md5（见 §6）。

## 3. 数据模型

### 3.1 新增 `LibraryBlob`
```go
type LibraryBlob struct {
    ID        uint      `gorm:"primaryKey"`
    MD5       string    `gorm:"size:32;uniqueIndex:uq_library_blobs_md5size,priority:1;not null"`
    SizeBytes int64     `gorm:"uniqueIndex:uq_library_blobs_md5size,priority:2;not null"`
    SliceMD5  string    `gorm:"size:32"` // md5(前 256KB)，秒传持有证明
    S3Key     string    `gorm:"size:512;not null"` // 物理对象 key（首个上传者的 key 直接收编）
    RefCount  int64     `gorm:"not null;default:0"`
    CreatedAt time.Time
    UpdatedAt time.Time
}
```
唯一键 `(md5, size_bytes)` —— 物理去重键。

### 3.2 `LibraryFile` 变更
- 新增 `BlobID uint`（`gorm:"index"`，删除时按它减引用）。
- 保留 `MD5`、`SizeBytes`（文件行冗余，列表/展示用）；新增持有 `SliceMD5`（可选，便于校验）。
- `S3Key` 改为**指向所属 blob 的物理 key**（去重后多个文件的 `S3Key` 相同）。所有读路径 `PresignGetURL(f.S3Key)` / `GetObject(f.S3Key)` 因此零改动。

### 3.3 迁移
`RegisterSetup` AutoMigrate 加 `library_blobs` 表 + `library_files.blob_id/slice_md5` 列（幂等）。存量文件 `blob_id=0`、走旧的「文件自有 S3Key、删除即删对象」路径（见 §7 兼容）。

## 4. 上传请求契约变更

`PresignUploadReq` 增加：
```ts
{ name, size_bytes, mime, folder_id, md5: string, slice_md5: string }
```
`PresignUploadResult` 增加：
```ts
{ file_id, upload_url?: string, s3_key?: string, expires_in?: number, instant: boolean }
// instant=true（秒传命中）：无 upload_url，文件已 active；前端跳过 PUT/confirm。
// instant=false：照常 PUT → confirm。
```

## 5. 上传流程

1. 前端流式读文件，算 `md5`（全量）+ `slice_md5`（前 256KB）+ `size`，调 `presign`。
2. 后端 `PresignUpload`（单事务，配合 §8 锁）：
   1. `reserveUpload`（配额按 `size` 照常校验+占位，配额不变）→ 建 uploading 文件行（记录 md5/slice_md5/size）。
   2. 查 blob `(md5, size)`：
      - **存在且 `slice_md5` 一致 → 秒传**：文件 `BlobID=blob.id`、`S3Key=blob.S3Key`、`blob.ref_count++`（行锁）、文件直接 `active` 并 `used_bytes+=size`；返回 `{file_id, instant:true}`。
      - 否则 → 返回 presigned PUT（key=`library/{uid}/{uuid}.ext`，存为该 uploading 文件的临时 key），`instant:false`。
3. 前端仅在 `instant:false` 时 PUT 到 `upload_url`，再调 `confirm{file_id}`。
4. `ConfirmUpload`：
   1. `Head(tempKey)` → `(realSize, etag)`；校验 `realSize==size` 且 `etag(=单段PUT md5)==声明 md5`，不符 → 删对象 + 拒绝。
   2. 再查 blob `(md5, size)`（行锁）：
      - **存在**：物理合并——`DeleteObject(tempKey)`，文件 `BlobID=blob.id`、`S3Key=blob.S3Key`，`blob.ref_count++`。
      - **不存在**：收编——以 `tempKey` 建 blob `{md5,size,slice_md5,s3_key=tempKey,ref_count=1}`，文件 `BlobID=blob.id`（`S3Key` 不变，已等于 tempKey）。
        - 并发：`(md5,size)` 唯一键冲突 → 回退到「存在」分支（回读 blob、`ref++`、删 tempKey）。
   3. 文件 `active` + `confirmActiveWithinCapacity`（`used_bytes+=size`，与现状一致）。

## 6. MD5 来源（S3 ETag）

`framework/s3` 新增：
```go
type HeadResult struct { Size int64; ETag string }
func (c *Client) Head(ctx, key) (HeadResult, error) // HeadObject → ContentLength + ETag
```
- ETag 去除两端引号；单段 PUT 时即文件 md5（32-hex）。
- 校验：`isHex32(etag)` 且 `etag == 声明 md5`。若 ETag 非 32-hex（极少，分段上传）→ 回退 `GetObject` 流式算 md5 再比对。
- 客户端提供的 md5/slice_md5 仅用于秒传查重；**confirm 一律服务端权威校验**，杜绝声明伪造影响真实上传链路。

## 7. 删除 + 引用计数 + 真删

- `DeleteFile`：软删文件行（`status=deleted, deleted_at`）。若 `blob_id>0`：`blob.ref_count--`（行锁事务）；减到 0 → 标记该 blob 待物理删除。
- cron（`cron.go`）改造，按 `blob_id` 分流：
  - **去重文件（`blob_id>0`）**：硬删软删文件行时**不**按文件删 S3（对象归 blob 所有）；S3 删除只由「孤儿 blob 清理」负责。
  - **存量文件（`blob_id=0`，旧路径）**：保持原逻辑——硬删前 `DeleteObject(file.S3Key)`（这条兼容分支保留）。
  - **孤儿 blob 清理（新增）**：扫 `ref_count<=0` 的 blob → 行锁内再次确认仍为 0 → `DeleteObject(blob.S3Key)` + 删 blob 行（防与并发新引用竞态）。
  - 通用：硬删已软删的文件行（`hardDeleteFile`）。

## 8. 并发与一致性

- blob `ref_count` 增减、归零真删，统一在 **blob 行锁**（`SELECT ... FOR UPDATE`，sqlite 退化为串行，复用 `lockUsageRow` 同款封装）内进行。
- 建 blob 靠 `(md5,size)` 唯一约束兜底：并发首传 → 一方建成，另一方唯一键冲突 → 回读 + `ref++` + 删自身 tempKey。
- 真删（ref→0）与并发新引用：减引用与「读 blob 决定秒传/合并」用同一把锁串行；归零删除在锁内再次确认 `ref_count==0`，并删除 blob 行，使后到的上传查不到该 blob → 走新建（重新上传物理对象）。
- 秒传与配额：秒传文件仍经 `reserveUpload`/`used_bytes+=size`，按逻辑文件计配额（配额不变）。

## 9. 前端

- 素材上传（MyFilesPanel）+ 应用上传弹窗（UploadAppDialog）：上传前**流式**算 `md5`（全量）与 `slice_md5`（前 256KB），用 `spark-md5`（apk 旧分片流程用过）。
- `presign` 带 `md5/slice_md5/size`；响应 `instant:true` → 跳过 PUT/confirm，提示「秒传成功」并刷新列表/容量。
- `instant:false` → 现有 PUT→confirm 流程不变。
- 大文件：流式分块读，避免一次性载入内存。

## 10. 错误处理

| 场景 | 行为 |
|---|---|
| confirm ETag md5 ≠ 声明 md5 / size 不符 | 删对象 + 拒绝（上传损坏或伪造） |
| 秒传查重命中但 slice_md5 不一致 | 不秒传，回退真实上传（§2 防护） |
| 并发首传唯一键冲突 | 回退合并分支（回读 blob + ref++ + 删 tempKey） |
| ETag 非 32-hex（分段上传） | 回退流式算 md5 校验 |
| 超额锁定 | `reserveUpload` 阶段照常拒绝（与现状一致） |

## 11. 测试

- blob 建/查/唯一键；秒传命中（同用户 & 跨用户，slice_md5 一致）；slice_md5 不一致 → 拒秒传走上传。
- confirm 物理合并（删 tempKey、指向旧 blob、ref++）；首传收编建 blob ref=1。
- 引用计数增减；最后引用删除 → cron 真删 S3 + 删 blob；非最后引用删除 → S3 对象保留。
- ETag 校验：md5 不符拒绝；分段 ETag 回退流式算 md5。
- 并发同文件首传（唯一键冲突回退）；ref→0 真删与并发新引用的锁串行。
- 配额不变（去重文件仍计自身大小）。
- 前端 `my` build；md5/slice_md5 计算正确（单测 spark-md5 包装）。
