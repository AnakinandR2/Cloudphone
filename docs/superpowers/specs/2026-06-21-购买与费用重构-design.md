# 购买与费用系统重构 · 设计文档

- 日期：2026-06-21
- 范围：`backend/modules/billing`（推倒重建）+ `backend/modules/phone`（增量改造）+ `my/`（购买页、费用日志页）+ `admin/`（配置后台）
- 状态：已通过脑暴评审，待写实现计划

## 0. 背景与目标

现有购买/费用体系语义重叠、重复严重：

- 三个 SKU（`instance_fee` / `boot_pack` / `time_pack`）语义混在一起；
- 余额既能直充又被订单扣，概念交叉；
- 发放额度有三条入口（购买→order、试用→claim、admin→adjust）无统一抽象；
- 折扣有两套（`DiscountTier` 阶梯 + `OrderItem.discount_bps` 手动），`discount_bps` 单位反直觉（10000=原价）。

本次用 DDD 统一语言重建概念，**一个钱包 + 三种可购买资源**，概念正交、消除重复，并新增"席位池热迁移 + 回收站"机制。

**前置决策（已与需求方确认）**：

| 决策点 | 结论 |
|--------|------|
| 席位底层模型 | 席位池（可热迁移） |
| 席位/包月数后端建模 | 方案 A · 统一「授权单元 License Unit」 |
| 开机扣费优先级 | 优先占用包月名额，名额满再扣临时时长 |
| 200 分钟/天封顶口径 | 按每台实例独立计算，封顶值 admin 全局可配 |
| 折扣叠加 | 数量阶梯折扣 × 时长折扣（相乘） |
| 旧数据 | 无生产数据，可推倒重建 |
| 试用 Trial | 保留并适配新模型 |
| 回收站 | 全新机制（phone 模块无软删除，现为硬删除） |
| 回收站恢复 | 手动恢复（用户自选，校验席位足够） |

## 1. 统一语言（Ubiquitous Language）

| 概念 | 类型 | 本质 |
|------|------|------|
| **余额 Balance** | 钱包 | 现金账户，运营可增减（须写理由）；支付一切（充值除外） |
| **实例席位 Seat** | 授权单元 `kind=seat` | "能存在"的权利。N 个未过期席位 → 最多 N 台实例 |
| **包月开机数 BootSlot** | 授权单元 `kind=boot_slot` | "能并发运行"的权利。N 个 → 最多 N 台同时开机；多实例轮流共享，同一时刻一台占用 |
| **临时开机时长 RuntimeMinutes** | 消耗池 | "能运行"的计量权利。无期限消耗，每台每天封顶 |

**关键关系**：席位决定能造几台；开机时**优先占空闲包月名额**，名额满了再扣临时时长；两者皆无则禁止开机。

**席位说明**：席位可单独/批量购买、单独/批量续费（不论当前是否有实例占用都可续）。实例自动分配席位；某席位过期但池中仍有余量时，实例热迁移到其他席位、无感知继续运行；席位过期且无可用席位时，超额实例停机进回收站。

**临时开机时长说明**：无使用期限，用完为止。开机满 1 分钟才算消耗 1 分钟，不满 1 分钟不消耗。每台手机每天最多扣 200 分钟（UTC+8，admin 可配），超过后当天继续使用不再扣。开机前校验账号是否有空闲包月名额或临时时长，没有则不允许开机。

## 2. 数据模型（重建 `billing` 模块）

### 2.1 钱包与流水

- `balance_accounts(user_id PK, balance_cents)` — 每用户一个钱包。
- `ledger_entries(id, user_id, subject, type, delta, balance_after, reason, ref_type, ref_id, created_at)` — 统一不可变流水，所有余额/资源变动都落账。
  - `subject`: `balance` | `seat` | `boot_slot` | `runtime_minute`
  - `type`: `topup`(充值) | `purchase`(购买) | `renew`(续费) | `runtime_consume`(运行扣临时时长) | `adjust_grant`(赠送) | `adjust_deduct`(扣减) | `trial`(试用)

### 2.2 授权单元（席位 + 包月数，统一表 — 方案 A）

- `license_units(id, user_id, kind, status, created_at, expire_at, source, source_ref, current_instance_id, order_item_id)`
  - `kind`: `seat` | `boot_slot`
  - `status`: `active`（未过期生效）| `expired`（已过期）
  - 占用关系由 `current_instance_id`（可空）体现，由 reconcile 物化
  - `source`: `order` | `trial` | `grant`
  - **可用池** = 同 `(user_id, kind)` 且 `status=active` 且 `expire_at > now` 的集合
  - **续费** = 对选中的单元 `id` 延长 `expire_at`

### 2.3 临时开机时长

- `runtime_minute_wallets(user_id PK, remaining_minutes)` — 余量快读副本（真相可由 ledger 推导，单独存一份用于快速展示与开机校验）。
- `runtime_daily_usage(user_id, instance_id, day_utc8, charged_minutes)` — 「某台·某天」已扣分钟，达封顶值停扣。

### 2.4 订单

- `orders(id, user_id, biz_type, status, total_cents, pay_method, created_at, paid_at, expired_at)`
  - `biz_type`: `recharge` | `seat_new` | `seat_renew` | `boot_slot_new` | `boot_slot_renew` | `runtime_pack`
  - `status`: `unpaid`（可继续支付）| `paid` | `expired`
- `order_items(id, order_id, target_kind, quantity, duration_value, duration_unit, unit_price_cents, qty_discount_bps, duration_discount_bps, amount_cents, renew_unit_ids)`
  - `duration_unit`: 席位=`month`，包月数=`day`
  - `renew_unit_ids`: 续费时记录续了哪些授权单元 ID

### 2.5 运行计费

- `runtime_charges(id, user_id, instance_id, run_session_ref, window_start, window_end, quota_type, charged_minutes, created_at)`
  - `quota_type`: `boot_slot`（占包月名额，charged=0）| `temp`（扣临时时长）| `capped_free`（当天超封顶，免费）
- 结算水位（幂等）：沿用 `RuntimeSettlementWatermark` 思路，按用户记录已结算到的时间点。

### 2.6 定价配置（admin）

支付方式（开关/排序）、充值预设金额、按 kind 的数量阶梯+折扣、按 kind 的时长选项+折扣、临时时长包预设+手输最低值+折扣、每分钟单价、各 kind 基础单价、200/天封顶值、回收站保留天数、各 kind 购买须知/计费说明文案。

> **折扣唯一真相在服务端**：`quote` 接口读配置算价，前端只展示。彻底取代旧的 `DiscountTier` + `OrderItem.discount_bps` 两套折扣。

## 3. 运行计费引擎

### 3.1 结算节奏

phone 模块每分钟同步开机流水（`RunSession`）并触发 `billing.SettleRuntime`；结算幂等，用水位防重复扣费。

### 3.2 满 1 分钟规则

按累计开机秒数向下取整到分钟：本次开机已运行 `floor((now - power_on)/60)` 分钟，减去「本开机会话已扣分钟」= 新增应扣。

- 例：14:32:32 开机 → 14:33:50 结算累计 78 秒 = 1 分钟 → 扣 1；下次满 2 分钟在 14:34:32。
- 不满 1 分钟即关机 → 不扣。

### 3.3 包月优先 + 临时回落（每 tick 核心逻辑）

对每个用户，取当前所有"运行中"实例，按 `power_on` 从早到晚排序：

1. 前 `N` 台（`N` = 当前可用包月名额数）→ 占包月名额，`quota_type=boot_slot`，不扣临时时长。
2. 第 `N+1` 台起 → 扣临时开机时长（按 3.2），`quota_type=temp`。
3. 某台当天已扣满封顶值（默认 200，UTC+8，admin 可配）→ 当天剩余时间**免费继续运行**（不停机），`quota_type=capped_free`。
4. 临时时长耗尽 **且** 无空闲包月名额 → 该台被 runtime guard 强制关机（保留最早开机、关最晚开机，沿用现有逻辑）。

**开机前置校验**：必须「有空闲包月名额」或「临时时长 > 0」，否则禁止开机（重写现有 `GetRuntimeCoverage` 检查）。

### 3.4 落账

每 tick、每台被计费实例写一条 `runtime_charges`；扣临时时长时同步写 `ledger_entries`（subject=`runtime_minute`）。

### 3.5 费用日志聚合（费用日志页）

后端分钟级记录，展示聚合到"开机会话"：同一实例、同一次开机（power_on→power_off / 运行中）的 `runtime_charges` 合并为一行：开机时段、占用类型（包月/临时/混合）、扣临时时长合计；混合段（中途名额释放或撞封顶）可展开看分段。页面顶部提示当天封顶规则。

## 4. 授权单元生命周期 + 回收站

### 4.1 reconcile 协调器（池化与自动分配）

`reconcileSeats(userID)` 在关键事件后触发（购买/续费席位、席位到期、创建/删除实例、定时巡检）：

1. 取未过期席位（按 `expire_at` 倒序）与非回收态实例（按 `created_at` 正序）。
2. 配对（zip）：物化到 `license_units.current_instance_id`，供续费 tab 展示"哪台实例坐哪个席位"。
3. 未过期席位数 ≥ 实例数 → 全部覆盖正常运行。
4. 未过期席位数 < 实例数 → 超额实例（最新创建优先）进回收站。

**热迁移 = 自动重配对**：具体席位 ID 过期时，只要池中仍有余量，reconcile 把实例重配到其他席位，实例无感知继续运行。

### 4.2 包月开机数生命周期

同为授权单元，同样池化/过期/续费，但不涉及回收站。名额到期 → 可用名额减少 → 若运行实例数 > 可用名额且临时时长不足 → runtime guard 关掉超额实例（仅关机，不回收不删数据）。

### 4.3 回收站（全新机制，落 phone 模块）

实例新增状态 `RECYCLED` + 字段 `recycled_at`、`recycle_reason`。

| 动作 | 触发 | 行为 |
|------|------|------|
| 进回收站 | reconcile 发现实例数 > 未过期席位数 | 超额实例（最新优先）强制关机 → 置 `RECYCLED` + `recycled_at`，释放席位占用 |
| 恢复 | 用户在回收站手动选择恢复 | 校验当前有空闲未过期席位才允许 → 置回 `STOPPED`，重新纳入 reconcile |
| 清理 | 每日定时任务 | `RECYCLED` 超保留天数（默认 30，admin 可配）→ 调 midplat 销毁 + 硬删本地记录，不可找回 |

回收站期间实例不占席位；数据保留至清理。

### 4.4 与现有代码衔接

- 复用 `TryOccupyInstanceSeat / ReleaseInstanceSeat / ReconcileInstanceSeats` 调用点，内部从"聚合计数"改为"授权单元池 + reconcile"。
- 现有欠费 `Dunning`（active/grace/frozen/recycled）保留，管"余额欠费"；与"席位过期回收"正交。**费用日志/状态展示需能区分两条回收路径**。

## 5. 用户前端（`my/`）

### 5.1 购买页骨架

顶部 4 张 KPI 卡片（余额[充值] / 实例席位 总X·已用Y[购买新实例][续费实例] / 临时开机时长 剩余N分钟[购买] / 包月开机数 总X·在用Y[购买][续费]）；内容区为 Tab 容器，点 KPI 按钮切 tab，默认显示订单历史。

### 5.2 原子可复用组件

| 组件 | 职责 |
|------|------|
| `PaymentBox` | 读 admin 支付方式（开关/排序）；`allowBalance` 开关（充值=false，其它=true）；确认支付 |
| `QuantityPicker` | 读 admin 数量档位；手输；展示当前数量命中的阶梯折扣 |
| `DurationPicker` | 读 admin 时长选项+折扣；不可手输；单位按 kind（席位=月、包月数=天） |
| `PurchaseNotice` | 按 kind 展示须知文案（admin 可配） |
| `OrderSummary` | 数量 / 折后单价 / 总价 / 到期时间（折扣相乘） |
| `UnitRenewTable` | 列未过期单元：ID/创建/到期/坐着的实例(名称,ID,状态)；多选；过滤器(到期/搜索名称或标签) |

### 5.3 组合面板（按 kind 参数化）

- `ProductBuyPanel(kind)` = `PurchaseNotice` + `QuantityPicker` + `DurationPicker` + 计费说明 + `OrderSummary` + `PaymentBox`
  - `kind=seat` → 购买新实例 tab；`kind=boot_slot` → 购买包月开机数 tab（时长按天）
- `ProductRenewPanel(kind)` = `UnitRenewTable` + 阶梯折扣展示 + `DurationPicker` + 计费说明 + `OrderSummary` + `PaymentBox`（续费实例 / 续费包月数共用）
- `RechargePanel` = 预设金额 + 手输 + `PaymentBox(allowBalance=false)`
- `RuntimePackPanel` = 须知 + 时长包按钮组/手输(≥admin最低值，享折扣) + `OrderSummary` + `PaymentBox`
- `OrderHistoryPanel`（默认 tab） = 全部订单：订单ID/时间/金额/状态（未支付→可继续支付 / 已支付 / 已过期）

### 5.4 数据流

- `GET /billing/overview` — 一次拿齐余额/席位用量/临时时长余量/包月用量（KPI）。
- `POST /billing/quote` — 服务端算折扣报价，前端不重算价。
- `POST /billing/orders` — 下单；余额支付即时扣，第三方支付走回调（网关本期 stub，但选择/排序/确认流程完整做）。
- 费用日志页：`GET /billing/runtime/log` — 返回聚合到开机会话的费用记录。

### 5.5 费用日志页

展示聚合开机会话：实例、开机时段（含"运行中"）、占用类型、扣临时时长合计；混合段可展开；顶部提示当天封顶规则。

## 7. 试用适配

保留 `TrialPolicy / TrialPolicyItem / TrialClaim / TrialGrant / TrialEligibility`。改动：

- 试用发放 subject 收敛为 `seat` / `boot_slot` / `runtime_minute`。
- 发放走与订单履约同一路径（`source=trial`）：发 seat/boot_slot → 创建 N 个 `license_units`（按 `ExpireDays` 设到期）；发 runtime_minute → 加临时时长余量。
- **三条入口（订单购买、试用、admin 赠送）统一收口到一个履约函数**（创建授权单元 / 加余量），消除旧系统三套发放路径的重复。

## 8. 上线策略（推倒重建）

无生产数据，可直接重建：

1. billing 模块表全部重建（AutoMigrate 新 schema，丢弃旧 `instance_fee`/`boot_pack`/`time_pack`/`EntitlementBatch` 等）。
2. phone 模块增量改造：新增 `RECYCLED` 态 + `recycled_at` + reconcile 协调器 + 每日清理 cron；`Power` 开机前置校验与 `GetRuntimeCoverage` 按新模型重写。
3. API 前缀保留 `/api/v1/billing`（用户）与 `/api/v1/admin/billing`（管理），路由按新 tab/页面调整。
4. i18n：`en.ts` / `zh-CN.ts` 新增购买页/费用日志/admin 配置文案键。

## 9. 建议实现分期（供写计划拆分）

1. **后端领域层**：授权单元 + 钱包 + 流水 + 订单/报价 + 履约函数（含试用/赠送）。
2. **后端运行计费**：结算引擎（满1分钟/包月优先/200封顶）+ `runtime_charges` + 费用日志聚合 API。
3. **后端生命周期**：reconcile + 热迁移 + 回收站（进/恢复/清理）+ phone 衔接。
4. **Admin 配置**：定价/折扣/支付/充值/须知/账户/试用。
5. **用户前端**：购买页（6 tab + 原子/组合组件）+ 费用日志页。
6. **联调 + i18n + 收尾**。

## 10. 非目标（YAGNI）

- 真实第三方支付网关对接（本期仅做支付方式选择/排序/确认流程 + 回调 stub）。
- 优惠券/促销码系统（折扣仅靠数量阶梯 × 时长，admin 可配）。
- 多租户/分级折扣等未在需求中提出的能力。
