# 素材库私有存储（专用私有桶 + 可配置签名时效）· 设计文档

- 日期：2026-06-25
- 范围：`backend/framework`（S3 客户端 + 配置）增量改造；`backend/modules/library`（切换私有桶 + 可配 TTL）；`backend/.env.example`（配置文档）。
- 前置：素材库主功能见 [2026-06-25-素材库-design.md](2026-06-25-素材库-design.md)。
- 状态：已通过脑暴评审。

## 0. 背景与问题

素材库要求是**私密存储**，不是"公开随时可拿链接下载"。当前实现已用 presigned 签名短链（私有桶模式），但探查发现一个真实漏洞：

- 框架的全局 S3 客户端 `framework.S3` 指向桶 `content-service`，且 `S3_PUBLIC_BASE_URL` 指向该桶。
- **`partner` 模块**（`modules/partner/internal/api.go:199`）把合伙人素材传到 `partners/<uuid>` 并用 `framework.S3.PublicURL()` 返回公开链接（供营销页等匿名访问）。这表明 `content-service` 桶是**公开读**的。
- **素材库文件目前也写在同一个公开桶**（key 形如 `library/{user_id}/<uuid><ext>`）。因此任何人只要拼 `S3_PUBLIC_BASE_URL/library/{user_id}/<uuid><ext>` 即可**绕过后端全部鉴权/属主/超额锁定校验直接下载**——presigned 短链在公开桶面前形同虚设。
- 旁证：`app` 模块的 APK 下载地址来自云手机中台，不经我们的 S3，不受影响。

**结论**：私密性的真正缺口是"素材库文件与公开资源同处一个公开桶"。需让素材库文件物理隔离到一个**私有桶**。

## 1. 目标

1. 素材库对象落在**专用私有桶**（无匿名读、无匿名 list），与 `partner` 用的公开桶分离。
2. presigned 签名有效期（GET/PUT）改为**后端环境变量可配**（替换硬编码常量）。
3. 整理 `.env.example`：补私有桶与 TTL 配置，澄清 `S3_PUBLIC_BASE_URL` 仅服务公开资源、素材库不使用。

**非目标（YAGNI）**：
- 后端代理流式下载（零链接暴露）——已决定保留 presigned + 私有桶方案。
- 既有对象迁移——素材库为新功能、无生产数据，私有桶从零开始。如未来已有数据，迁移脚本另行处理。
- 改动 `partner`/`www` 的公开访问链路。

## 2. 方案：素材库专用私有桶（Approach A）

物理隔离：素材库用独立私有桶，公开资源（partner）保持公开桶 `content-service`。改动最小、隔离最强、不波及 partner 公开能力。

（已否决：B 整桶私有 + partner 改 presigned——波及营销页匿名访问；C 同桶逐对象 ACL——依赖桶策略，脆弱易配错、匿名 list 仍可能泄露。）

## 3. framework 改造（`backend/framework`）

### 3.1 第二个 S3 客户端：`framework.S3Library`

- `framework/config.go` 新增配置字段与 env：
  - `S3LibraryBucket`（env `S3_LIBRARY_BUCKET`，默认 `""`）：素材库专用私有桶名。
  - `S3PresignGetTTL`（env `S3_PRESIGN_GET_TTL`，默认 `15m`）、`S3PresignPutTTL`（env `S3_PRESIGN_PUT_TTL`，默认 `30m`）：解析为 `time.Duration`；解析失败或 ≤0 回退默认（新增 `getEnvAsDuration(key, default)` 辅助）。
- `framework/s3client.go` 的 `InitS3()`：在构造主客户端 `framework.S3`（公开桶，带 `PublicBaseURL`）后，额外构造 `framework.S3Library`：
  - 复用同一 `Endpoint/Region/AccessKeyID/SecretAccessKey/UsePathStyle`。
  - `Bucket = S3LibraryBucket`（非空时）；**`PublicBaseURL` 置空**（私有桶不应有公开前缀，防御性杜绝 `PublicURL` 产出可用链接）。
  - **回退**：`S3_LIBRARY_BUCKET` 为空 → `framework.S3Library = framework.S3`（复用主桶）并 `log.Println` WARNING：「素材库未配置专用私有桶（S3_LIBRARY_BUCKET），回退共享桶，私密性降级，生产环境请配置独立私有桶」。
  - 若 AK/SK/Bucket 缺失（主客户端未初始化）→ `framework.S3Library = nil`，与现状一致（library 接口返回 503）。
- 将主客户端构造逻辑抽出复用（避免重复 endpoint/creds 装配代码）。

### 3.2 配置日志

`config.go` 启动日志补打 `S3LibraryBucket`、`S3PresignGetTTL`、`S3PresignPutTTL`（敏感值不打印 AK/SK，沿用现有 `displayOrEmpty`）。

## 4. library 改造（`backend/modules/library`）

- `files.go`：把所有 `framework.S3`（presign/head/delete）调用切换为 **`framework.S3Library`**；nil 校验改判 `framework.S3Library == nil`（503 文案不变）。涉及点：`PresignUpload`、`ConfirmUpload`、`DownloadFile`、`OpenFile`、`ListUsableFiles`、删除/cron 清理 S3 对象处。
- 删除硬编码常量 `presignGetExpiry = 15m` / `presignPutExpiry = 30m`，改读 `framework.AppConfig.S3PresignGetTTL` / `S3PresignPutTTL`（在 service 构造时注入或调用处读取；优先在 `module.Init` 注入到 service，便于测试）。
- `PresignUploadResult.ExpiresIn` 反映配置后的 PUT TTL（秒）。
- 不引入任何 `PublicURL` 调用（现状已无）。

## 5. `.env.example` 整理（`backend/.env.example`）

S3 段补充并澄清：

```
# S3_BUCKET：公开资源桶（partner 合伙人素材等，经 S3_PUBLIC_BASE_URL 公开访问）。
S3_BUCKET=
# S3_LIBRARY_BUCKET：素材库专用【私有】桶（无匿名读、无匿名 list）。
#   与公开桶分离，确保素材库文件只能经后端鉴权后用 presigned 短链访问，无法被匿名拼链接下载。
#   留空则回退共享 S3_BUCKET（私密性降级，生产不推荐）。复用上面的 Endpoint/Region/AK/SK/PathStyle。
S3_LIBRARY_BUCKET=
# 签名短链有效期（Go duration，如 15m / 5m / 1h）。素材库 presigned 下载/上传链接时效。
S3_PRESIGN_GET_TTL=15m
S3_PRESIGN_PUT_TTL=30m
# S3_PUBLIC_BASE_URL：仅用于【公开资源】（partner）的公开/CDN 前缀；素材库不使用、不暴露公开链接。
S3_PUBLIC_BASE_URL=
```

> 运维须知（写入注释）：素材库私有桶必须在对象存储侧配置为私有（关闭匿名读与匿名 list）；presigned 短链是唯一访问路径。

## 6. 测试

- `framework` 单测：
  - `getEnvAsDuration`：合法值解析、非法值/空值回退默认、≤0 回退默认。
  - `InitS3` 行为（可在不真连 S3 的前提下断言配置装配）：`S3_LIBRARY_BUCKET` 设置时 `S3Library` 用该桶且 `PublicBaseURL` 为空；为空时回退主桶；AK/SK 缺失时 `S3` 与 `S3Library` 均 nil。
- `library` 单测/既有用例不回归：presign 用注入的 TTL；`framework.S3Library == nil` 时相关接口返回 503（沿用 `TestLibraryPresignWithoutS3Returns503` 的等价断言，改判私有桶客户端）。
- 验证：`go build ./...`、`go vet ./...`、`go test ./...`。
