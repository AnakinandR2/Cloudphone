# 支付方式手续费配置 — 设计文档

> 日期：2026-06-25
> 范围：为支付方式增加可配置手续费（比例 + 固定，可叠加），并在用户结账的账单小结、订单历史/详情与运营查账中体现。
>
> 文中的 file:line 主要以**符号名 + 文件**为准（行号会随编辑漂移，仅作定位提示）。

## 1. 背景与目标

每个支付方式需支持配置手续费，手续费分两类、可叠加：

- **比例手续费**：按订单金额的百分比收取（如 2%）。
- **固定手续费**：每笔固定金额（如 ¥1）。

两者叠加示例：`2% + ¥1`。**任一项配置为 0 等于没有该项手续费**；两项都为 0 等于该支付方式不收手续费。

**关键语义决策（已与需求方确认）：**

1. **外加（用户多付）**：手续费叠加在订单金额之上，用户实付 = 订单金额 + 手续费。
   - 充值面额 ¥100、配 `2%+¥1` → 用户实付 ¥103，到账余额 ¥100。
   - 购买席位应付 ¥50 → 实付 ¥51。
   - 比例手续费的**基数 = 订单金额**（购买为折后应付金额，充值为充值面额）。
2. **余额支付零手续费**：账户余额是充值进来的（充值时已收过一次手续费），用余额购买不再收，避免双重收费。
   - 实现上**计算逻辑统一按配置收**，不对余额做特判；
   - 由"保存校验"保证余额方式（`code == "balance"`）的手续费配置恒为 0：前端禁止填写，后端校验拒绝非 0。
3. **货币单位**：系统金额一律以「分」（int64 cents）存储与计算，前端按 `zh-CN`/¥ 展示。需求中的 `$1` 为举例，固定手续费以系统货币的「分」存储。本设计不引入多币种。

**成功标准：**

- 运营后台可为每个支付方式配置比例 + 固定手续费；余额方式被禁止配置非 0。
- 用户结账（购买/续费/充值）时，账单小结正确显示手续费与实付金额。
- 订单历史与详情、运营查账页能看到手续费与实付，可对账。
- 后端权威计算并固化手续费到订单，前端展示与后端结果一致。
- 历史订单与旧配置向后兼容（视为无手续费）。

## 2. 架构方案

采用**方案 A：订单固化手续费快照 + 前端实时预览 + 后端权威重算**。

- 支付方式模型携带手续费配置，随 `purchase-config` 接口自动下发到前端，前端切换支付方式即时算出手续费用于预览。
- 订单新增手续费金额字段与配置快照字段；`total_cents` 语义不变（商品/充值金额），实付 = `total_cents + fee_cents`。
- 下单时后端按所选支付方式**权威重算**手续费并固化到订单，前端确认页以后端返回值为准。

> 已排除：方案 B（把手续费合并进 `total_cents`，丢失明细、污染语义、无法对账）；方案 C（手续费做成独立订单项 `BizOrderItem`，污染履约逻辑、统计复杂）。

## 3. 数据模型

### 3.1 `PaymentMethod`（手续费配置）

文件：`backend/modules/billing/internal/pricingconfig_model.go`，`PaymentMethod` 结构体。存储于 `billing_pricing_config` 表的 `PaymentMethodsJSON`（text 列，单行 JSON 配置，id 固定 1）。

```go
type PaymentMethod struct {
    Code          string `json:"code"`
    Name          string `json:"name"`
    Enabled       bool   `json:"enabled"`
    Sort          int    `json:"sort"`
    FeePercentBps int    `json:"fee_percent_bps"` // 比例手续费，基点(200=2%)；0=无
    FeeFixedCents int64  `json:"fee_fixed_cents"` // 固定手续费，分(100=¥1)；0=无
}
```

- **基点（bps）**沿用项目折扣惯例（10000 = 100%）；`2% = 200 bps`。
- JSON 存储，**无需数据库迁移**；旧配置缺这两个字段时反序列化为 0，等于无手续费，天然向后兼容。
- seed 默认值（`pricingconfig_repository.go` 的 `defaultPricingConfig()` 内 `PaymentMethods`）三个支付方式（balance/wechat/alipay）的 fee 字段保持默认 0。

### 3.2 `BizOrder`（订单固化手续费）

文件：`backend/modules/billing/internal/bizorder_model.go`，`BizOrder` 结构体。新增三字段：

```go
FeeCents      int64 `gorm:"not null;default:0" json:"fee_cents"`       // 实收手续费（分）
FeePercentBps int   `gorm:"not null;default:0" json:"fee_percent_bps"` // 下单时配置快照
FeeFixedCents int64 `gorm:"not null;default:0" json:"fee_fixed_cents"` // 下单时配置快照
```

- `BizOrder` 已在 `module.go` 的 `AutoMigrate` 列表中，会自动加列，默认 0；历史订单 = 无手续费。
- `total_cents` **语义不变**（商品/充值金额）。**实付 = `total_cents + fee_cents`**。
- 两个快照字段记录下单当时的配置，保证日后修改支付方式配置不影响历史订单的对账与展示。
- **数据库前提**：后端默认 SQLite（`go test`/本地默认）。SQLite `ALTER TABLE ADD COLUMN ... NOT NULL DEFAULT 0` 对既有行安全回填。若生产使用 MySQL/Postgres，该 DDL 在大表上可能短暂锁表，建议低峰执行。

## 4. 计算逻辑（后端权威）

### 4.1 工具函数

文件：`backend/modules/billing/internal/pricing.go`。复用现有 `applyBps`（同文件，按基点计价、四舍五入到分，round-half-up）。

```go
// computeFee 计算外加手续费 = 比例(基数×bps，四舍五入到分) + 固定。
// 基数<=0（含 0 元订单）时不收任何手续费（含固定部分）。
func computeFee(baseCents int64, percentBps int, fixedCents int64) int64 {
    if baseCents <= 0 {
        return 0
    }
    return applyBps(baseCents, percentBps) + fixedCents
}
```

### 4.2 接入下单流程

文件：`backend/modules/billing/internal/bizorder_service.go`，`CreateOrder`——充值、新购、续费均在此创建订单。

`order.TotalCents` 对三种 biz_type 的赋值（已核实）：充值 = `req.AmountCents`（面额）、新购/续费/时长包 = `q.PayableCents`（折后应付）。手续费基数统一取 `order.TotalCents`。

**接入步骤（注意时机）：在 `order.TotalCents` 确定之后、`s.repo.create(&order, ...)` 之前——**

1. 取所选 `pay_method` 的配置：`bizOrderServiceImpl` 已持有 `PricingConfigService`（`module.go` 注入，字段 `s.pricing`）。经 `s.pricing.Get().PaymentMethods` 取列表，**按 code 匹配**（无现成 by-code 方法，自行遍历或新增 `PaymentMethodByCode` helper）。
2. 计算 `fee = computeFee(order.TotalCents, pm.FeePercentBps, pm.FeeFixedCents)`。
3. **在 `create` 之前**写入 `order.FeeCents`、`order.FeePercentBps`、`order.FeeFixedCents`——`create` 用 `tx.Create` 一次性按当前结构体字段入库，之后无 Update 回写；若在 create 之后赋值，fee 三字段不会落库。

**`pay()` 扣款**：当前真正动余额的只有 `if o.PayMethod == PayBalance && o.BizType != BizRecharge` 分支（`wallet.Charge(userID, o.TotalCents, ...)`）。唯一需改动的扣款行是把该处的 `o.TotalCents` 改为 `o.TotalCents + o.FeeCents`：

- **余额支付**：余额方式 fee 恒为 0，等价于扣 `TotalCents`，行为不变（双保险，即便配置异常也不会破坏）。
- **第三方支付 / 充值**：当前为桩网关，不走 `wallet.Charge`。`total+fee` 仅体现在持久化的 `fee_cents` 与未来真实网关对接，本期不改其资金流。
- **充值到账**：`fulfillOrder` 的充值分支 `TopUp(TotalCents)` 只 +面额，手续费不进余额——符合"外加"语义。

> 计算逻辑统一不对余额特判（符合需求方要求）；余额零手续费由第 5 节保存校验保证。

### 4.3 下单时支付方式校验（消歧）

`CreateOrder` 现仅查硬编码白名单 `validPayMethods`（`bizorder_model.go`，`{balance,wechat,alipay}`）。新增规则：

- `pay_method` 必须 (a) 在 `validPayMethods` 白名单内（防御），且 (b) 命中 `s.pricing.Get().PaymentMethods` 中某条且 `Enabled == true`，否则拒绝下单（前端只展示 enabled 方式，后端兜底拒绝被禁用/已删方式）。
- fee 取该命中配置的 `FeePercentBps`/`FeeFixedCents`。
- 容错：若 `pay_method` 在白名单但配置列表缺失（理论上配置应覆盖白名单），按 `fee=0` 处理、不阻断下单（向后兼容）。

### 4.4 手续费收入对账口径

手续费收入以订单 `fee_cents` 为权威记录。运营对账/统计按订单聚合 `SUM(fee_cents)`（可按 `pay_method` 分组）即可。**不新增 ledger 流水类型**——余额支付 fee 恒 0、第三方不进余额，给余额 ledger 加 fee 类型反而误导。

## 5. 配置校验（保存支付方式）

文件：`backend/modules/billing/internal/billing2_api.go`，`AdminSavePaymentMethods`（当前无校验）。保存前逐条校验，任一条不通过返回 400 与明确错误信息：

- `FeePercentBps ∈ [0, 10000]`（0–100%）；
- `FeeFixedCents ≥ 0`；
- **`code == "balance"` → `FeePercentBps` 与 `FeeFixedCents` 必须都为 0**，否则拒绝。

> 权限复用既有 `billing:manage`（PUT）/ `billing:view`（GET），**不新增权限点**，无需改 `permissions.go`。

## 6. API 变更

| 接口 | 变更 |
| --- | --- |
| `GET /billing/purchase-config`（`GetPurchaseConfig`） | 返回的 `payment_methods` 自动携带 `fee_percent_bps` / `fee_fixed_cents`（直接序列化 `cfg.PaymentMethods`，handler 无需改动） |
| `GET /admin/billing/payment-methods`（`AdminGetPaymentMethods`，权限 `billing:view`） | 自动携带 fee 字段 |
| `PUT /admin/billing/payment-methods`（`AdminSavePaymentMethods`，权限 `billing:manage`） | 接收 fee 字段并**新增第 5 节校验** |
| `POST /billing/orders`（`CreateBizOrder`） | 后端返回结构体为 **`BizOrderResult{Order, Pay}`**（`bizorder_model.go`）。`fee_cents`/`fee_percent_bps`/`fee_fixed_cents` 随 `BizOrder` 自动进入 `res.order`。**不新增后端 `pay_cents` 字段**，前端从 `order.total_cents + order.fee_cents` 自行派生实付 |
| `GET /billing/orders`（列表，`ListBizOrders`） | 走 `OKWithPage` 直接序列化 `BizOrderWithItems`（内嵌 `BizOrder`），**自动携带** fee 字段；历史订单为 0 |
| `GET /billing/orders/:id`（`GetBizOrder`）<br>`GET /admin/billing/biz-orders/:id`（`AdminGetBizOrder`） | **不自动携带**——这两个 handler 手拼 `gin.H` 仅挑选固定字段。需**显式补加** `fee_cents`/`fee_percent_bps`/`fee_fixed_cents` 三个键，否则详情页拿不到 |

> `POST /billing/quote`（`BizQuote`）**不改动**：手续费依赖所选支付方式，而 quote 不传 `pay_method`。前端用 `quote.payable_cents`（或充值面额）+ 选中支付方式的 fee 配置自行实时计算预览，下单时由后端权威重算。
>
> **营销站 www/ 无影响**：公开营销接口（`billing_public_api.go` 的 `OpenGetPricing`）不下发 `payment_methods`，www/ 不消费支付方式，故 struct 扩展不会泄露 fee 字段、无需改动 www/。

- `my/src/mock/billing.ts`：`payment_methods` 三条补 fee 字段（balance 全 0；wechat/alipay 可给示例 200/100 便于演示）；mock 下单响应/订单数据补 `fee_cents` 等。
- `admin/src/mock/billing.ts`：`paymentMethods` 三条补 fee 字段（balance 全 0）；mock 订单数据补 fee。

新增文案必须同时加 `zh-CN.ts` 与 `en.ts`：

### 7.3 运营后台 admin/

`admin/src/views/billing/PaymentMethodsView.vue`：每个支付方式编辑行新增「比例手续费 (%)」「固定手续费 (¥)」两个输入。

- 保存时换算：`% → bps`（×100，如 2 → 200）、`¥ → cents`（×100，如 1 → 100）；读取时反向换算用于展示。
- `code === "balance"` 行：两个输入 **disable 且固定显示 0**（前端兜底，后端校验为最终保证）。

`admin/src/views/billing/BillingOrdersView.vue`：订单列表/详情展开补「手续费 / 实付」展示（运营查账可见手续费收入与用户实付）。

### 7.4 用户后台 my/

- `my/src/utils/money.ts`：新增 `computeFeeCents(baseCents, percentBps, fixedCents)`，与后端 `computeFee` **同公式同舍入**（`base<=0` 返回 0，比例用 `Math.round(base*bps/10000)` 与 `applyBps` round-half-up 对齐），用于实时预览。
- `my/src/views/billing/purchase/PaymentBox.vue` 与各父面板：PaymentBox 已通过 `v-model` 把选中 `code` 暴露给父面板。**父面板用选中 `code` 从 `config.payment_methods` 反查 fee 配置**传给 `OrderSummary`，无需新增 emit。
  - 余额充足性校验保持不变：余额方式 fee 恒 0，PaymentBox 的 `amountCents` 仍传应付/面额基数；非余额方式无需余额校验。
- `my/src/views/billing/purchase/OrderSummary.vue`：接收 fee（或选中方式配置）作为新 prop，账单小结新增——
  - 「手续费」行：`fee > 0` 时显示，标注构成（如 `2% + ¥1`）；
  - 「实付」行 = 折后应付 + 手续费，作为**唯一突出**的最终金额（大字红色加粗）；
  - **主次降权**：存在手续费时，把现有「应付总价」行降为常规字重/普通色作为小计；`fee == 0` 时维持现有「应付总价」突出样式不变（不显示手续费/实付行）。
- `my/src/views/billing/purchase/RechargePanel.vue`：把现有「应付」区扩成小结（充值金额 → 手续费 → 实付）。
  - 代表面额的那行标签改用新 key `rechargeFaceAmount`（充值金额/面额），**不要复用「应付金额」**（否则出现「应付 < 实付」的反直觉表述）；最终大字红色突出「实付」。
  - 充值经 `createOrder2({biz_type:'recharge', pay_method})` 提交，与购买共用后端集成点。
- `my/src/views/billing/purchase/ProductBuyPanel.vue`、`ProductRenewPanel.vue`、`RuntimePackPanel.vue`：用选中支付方式的 fee 传入各自的 `OrderSummary`。
- `my/src/views/billing/purchase/OrderHistoryPanel.vue`：订单金额列旁或行展开明细补「手续费 / 实付」。

### 7.5 数据流

选支付方式 → 父面板用选中 code 从 `config.payment_methods` 反查 fee 配置 → `computeFeeCents` 实时算手续费 → 小结展示实付 → 点支付 → `createOrder2(pay_method)` → 后端按所选方式权威重算并在入库前固化 → 返回 `order.fee_cents` → 前端确认页以后端值为准（`pay = order.total_cents + order.fee_cents`）。

## 8. 边界与错误处理

- **向后兼容**：旧 `PaymentMethodsJSON`、旧订单缺字段一律反序列化/默认为 0 = 无手续费。
- **0 元订单**：`computeFee` 基数 ≤ 0 返回 0，不对 0 元订单收取固定费。
- **舍入一致**：前后端共用 `base × bps / 10000` 四舍五入到分；同公式同输入不会漂移；确认页一律以后端 `order.fee_cents` 为最终值。
- **余额双保险**：保存校验拒绝余额非 0 配置；计算逻辑保持统一不特判，即使配置异常也不破坏既有余额扣款行为。
- **非法/禁用支付方式**：见 §4.3——白名单 + 配置命中 + `enabled` 三重校验，拒绝被禁用/已删方式。
