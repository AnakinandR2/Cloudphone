# 云手机：移除「地区」+ 强制绑定代理才能开机 + 绑定代理改表格选择

> 日期：2026-06-22 ｜ 范围：`backend/`（phone 模块）+ `my/`（用户前台）+ `admin/`（实例管理视图，仅去地区列）

## 背景与目标

云手机当前带一个「地区(region)」字段，对现阶段业务无用；同时业务上要求「云手机必须绑定代理后才能开机」。本次改动：

1. **移除云手机的「地区」**：前后端不再存储/展示/录入云手机的 region（注意：**代理(proxy) 自身的 region 保留**，那是代理出口归属，与云手机地区是两码事）。
2. **强制绑定代理才能开机**：开机前置校验新增「必须已绑定代理（proxy_id>0）」，未绑定一律拒绝开机。
3. **创建时可暂不绑代理，但要提醒**：创建对话框允许不选代理直接创建，但显式提示「创建后必须绑定代理才能开机」。
4. **绑定代理交互改造**：原「绑定代理 ID」下拉框 → 改名「绑定代理」，改用**表格**选择，表格列为：代理 ID、地址、IP 信息、已绑定数量；并在该处提示**跳转到「代理管理」**页。

## 现状关键事实（已核对代码）

- 后端 `modules/phone`：`CloudPhone` 模型有 `Region`；`CloudPhoneCreate/Update` 有 `Region`；`Create` 透传给中台 `CreateArgs.Region`（`midplat.go` 里 `RegionOption:"CUSTOM" + Region:args.Region`）；`recycle.go` 的 `RecycleBinItem` 也带 `Region`。实际上前端创建对话框**早已不暴露 region 输入**（恒传空串），所以中台 create 当前就一直收到空 region —— 移除该字段对中台调用**行为不变**。
- 后端 `Power`（`service.go` 开机分支）：已有 `billing.CanBoot` 名额校验，但**没有**代理校验。`model.go` 注释（`ProxyID ... 未绑代理不可开机，校验属后续阶段`）即预留此处。
- 绑定代理：前端经通用 `PUT /phone/update/{id}` 带 `proxy_id` 完成，无专用接口；当前 UI 是 `NativeSelect` 下拉（`PhoneFormDialog.vue`），数据来自 `GET /proxy/options`。
- 「已绑定数量」= 某代理被当前用户多少台云手机绑定。云手机列表（`phoneApi.list`）已返回每台的 `proxy_id`，**可在前端按用户自有手机列表聚合得到**，无需后端新接口、无需跨模块依赖。
- 代理管理页路由：`/proxy`（`routes.ts`，name=`proxy`）。
- 模块边界（`framework/arch_test.go`）：禁止 import 别模块的 `internal`；本方案不新增任何跨模块依赖。
- 测试基建：后端 `go test ./...`（真实 sqlite，fakePort 注入中台）；前端 `vitest`（jsdom + @vue/test-utils 已具备），纯函数测试惯例见 `views/phone/remoteWindowFit.ts`+`.test.ts`。

## 方案

### A. 移除「地区」（云手机）

**后端（`modules/phone`）**
- `model.go`：从 `CloudPhone`、`CloudPhoneCreate`、`CloudPhoneUpdate` 删除 `Region` 字段。
  - DB 列不删（GORM AutoMigrate 不会 drop 列；遗留空列无害、幂等启动不受影响）。
- `service.go`：`Create` 不再写 `item.Region` / 回填 `res.Region`；`updateFields` 删 region 分支；`s.ops.Create` 入参去掉 Region。
- `midplat.go`：`CreateArgs`/`CreateResult` 删 `Region`；`CreateCloudPhones` 请求里删除 `Region: args.Region`（保留 `RegionOption:"CUSTOM"`，与今天「空 region」行为一致）。
- `recycle.go`：`RecycleBinItem` 删 `Region` 及其赋值。
- 受影响测试：`service_test.go`、`state_test.go`、`ops_test.go` 中出现的 `Region: "上海"` / `CreateResult{...Region}` 一并删除。

**前端 `my/`**
- `types/phone.ts`：`CloudPhone`/`CloudPhoneCreate`/`CloudPhoneUpdate` 删 `region`。
- `views/phone/PhoneFormDialog.vue`：`emptyForm` 删 `region`；create/update 提交体删 `region`。
- `views/phone/PhoneView.vue`：删表格 region 列、`#cell-region`、卡片 region 行、行展开 region 项、`filteredData` 里按 region 的关键词匹配。
- `locales/zh-CN.ts`、`en.ts`：删 `phone.colRegion`、`phone.fRegion`、`phone.fRegionPlaceholder`（**保留** `proxy.colRegion`）。
- `mock/phone.ts`：内存表与 create/update 去掉 `region`。

**前端 `admin/`（避免实例列表残留空「地区」列）**
- `views/ops/InstanceView.vue`：删 region 列定义与 `#cell-region`（保留第 84 行代理地址映射里的 `p.region`，那是代理 region）。
- `types/instance.ts`：删实例 `region`。
- `locales/zh-CN.ts`、`en.ts`：删 `instance.colRegion`。
- （`admin/views/cloudphone/*`、`types/cloudphone.ts` 的 region/regionName 是「地区/可用区目录」资源，**不动**。）

### B. 开机必须已绑定代理

`service.go` 的 `Power` 开机分支，门禁顺序：**实时态 → 状态可开机(CREATED/STOPPED) → 已绑代理 → CanBoot 名额**。新增：

```go
if p.ProxyID == 0 {
    return apperr.Validation("未绑定代理，无法开机，请先绑定代理")
}
```

- 放在 CanBoot **之前**，给出更明确的「先绑代理」提示。
- 只校验 `proxy_id != 0`（不校验代理是否仍存在/归属）——保持简单；绑定动作本身已是用户从自己代理列表里选的；后续如需可再加归属校验。
- 测试适配：把共享夹具 `insertPhone`、`provisionedPhone` 默认带上 `ProxyID: 1`，使既有开机用例继续通过；新增 `TestPowerOnRequiresProxy`：proxy_id=0 且实时态 STOPPED → 开机被拒（错误信息含「代理」）。

### C. 创建时可暂不绑代理 + 提醒

`PhoneFormDialog.vue` 创建态：当 `proxy_id===0` 时，在绑定代理区域下方显示**琥珀色提醒**：「未绑定代理：创建后需绑定代理才能开机」。不阻断创建（按需求允许暂不绑）。

### D. 绑定代理：表格选择 + 跳转代理管理

`PhoneFormDialog.vue` 内，把原 `NativeSelect` 替换为表格选择控件：

- 标题/标签：`绑定代理`（不再叫「绑定代理 ID」）。
- 数据：
  - 代理来源：`proxyApi.list({page:1,size:999})`（含 host/port/egress_ip/country/city/status 等）。
  - 已绑定数量：由父组件 `PhoneView` 把已加载的 `data`（本人全部云手机）作为 `:phones` prop 传入对话框，前端纯函数 `countBoundProxies(phones) → Map<proxyId, count>` 聚合得到（无额外请求、无后端改动）。
- 表格列：**代理 ID** ｜ **地址**（`protocol://host:port`）｜ **IP 信息**（出口 IP + 国家/城市，未测则「未测试」）｜ **已绑定数量**。
- 选择方式：每行一个单选（radio），外加一行「不绑定」（proxy_id=0）。选中即写 `form.proxy_id`。
- 空态：无代理时显示「您还没有添加代理」+ 跳转链接。
- 跳转提示：表格区域附 `RouterLink to="/proxy"`「前往代理管理」（点击后路由切换、对话框关闭，符合「提示跳转」）。
- 纯逻辑抽到 `views/phone/proxyBind.ts`（`countBoundProxies`、`formatProxyAddress`、`formatProxyIp`），配 `proxyBind.test.ts` 单测。

### E. 开机前端引导（未绑代理）

`PhoneView.vue` 的 `powerOn(row)`：若 `row.proxy_id===0` → `toast.error('请先绑定代理后再开机')` 并打开该机的编辑对话框（含绑定代理表格），不调用开机接口。后端门禁仍是兜底。

## 数据流

```
创建/编辑对话框打开
  → proxyApi.list(全部代理)            // 表格行
  → props.phones (本人云手机列表)        // countBoundProxies → 每个代理已绑定数量
用户选某行 / 选「不绑定」 → form.proxy_id
提交 → phone/create | phone/update { …, proxy_id }   // region 不再发送
开机 → 前端先判 proxy_id>0（否则引导绑定）→ POST /phone/{id}/power
       后端 Power：实时态→状态门禁→proxy_id>0→CanBoot→中台开机
```

## 影响面与边界

- 不新增后端接口、不新增模块依赖、不改 DB 迁移系统（遗留 region 列无害）。
- 代理自身 region 全程保留。
- 中台 create 调用行为不变（今天就传空 region）。
- 兼容：历史云手机 `proxy_id=0` 的，开机会被拦截并提示绑定 —— 这正是期望行为。
