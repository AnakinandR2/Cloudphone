# 支付手续费可对比展示 + 满额免手续费 — 设计文档

> 日期：2026-06-25
> 范围：在已有「支付方式手续费」功能（commit `37fc1a1`）之上增强两点——(1) 每个支付方式直观展示其手续费、并在结算单手续费行体现渠道 logo；(2) admin 可按渠道配置「满额免手续费」阈值，结算单给出 ? 提示并在达标后对手续费金额加删除线。
>
> file:line 以符号名 + 文件为准（行号仅作定位提示）。

## 1. 背景与目标

现状（见截图）：结算单只有一行「手续费 (0.5%+¥1.00) ¥1.05」，用户无法把手续费关联到具体渠道，也无法横向对比「换支付宝是否更便宜」。同时缺少「满额免手续费」这类促销能力。

**目标：**

1. **可对比**：在 PaymentBox 每个支付方式卡片里展示该渠道在当前订单金额下的手续费，用户一眼对比。
2. **渠道关联**：结算单「手续费」行带上选中渠道的 logo，体现手续费由该渠道产生。
3. **渠道 logo 可配置**：admin 在支付方式配置里可上传 logo 或填写 logo URL；默认 seed 微信/支付宝 logo。
4. **满额免手续费**：admin 可为每个渠道配置阈值——订单（加手续费前）金额 ≥ 阈值则免手续费；阈值为 0 表示永不免除。结算单手续费行带 ? 气泡提示「订单金额满 ¥xx 免手续费」，达标后手续费金额呈删除线、实付不含手续费。

**已确认的决策：**

- **logo 形式**：`PaymentMethod` 新增 `logo_url` 字段；admin 可上传图片（复用 partner 的上传端点模式）或直接填 URL。seed 默认微信/支付宝 logo（外部 CDN，admin 可后续替换为自有存储）。
- **卡片手续费展示内容**：**只显金额**（最简洁、便于对比）。满额免显示「免手续费」，无手续费配置显示「无手续费」。阈值详情放结算单的 ? 气泡。
- **阈值比较基数**：订单加手续费前的金额，即 `order.TotalCents`（购买=折后应付、充值=面额）；`base >= threshold` 即免（`>=`，"满"）。

## 2. 数据模型

### 2.1 `PaymentMethod`（[pricingconfig_model.go](backend/modules/billing/internal/pricingconfig_model.go) 的 `PaymentMethod`）

新增 2 字段：

```go
LogoURL               string `json:"logo_url"`                 // 渠道 logo（上传得到的 URL 或手填 URL）；空=无
FeeFreeThresholdCents int64  `json:"fee_free_threshold_cents"` // 订单(加费前)金额≥此值免手续费，分；0=永不免
```

- JSON 存储，无需 DB 迁移；旧配置缺字段反序列化为空串/0，向后兼容。

### 2.2 `BizOrder`（[bizorder_model.go](backend/modules/billing/internal/bizorder_model.go) 的 `BizOrder`）

新增 1 个快照字段：

```go
FeeFreeThresholdCents int64 `gorm:"not null;default:0" json:"fee_free_threshold_cents"` // 下单时阈值快照
```

- 配合已有 `fee_cents`（实收，0 可能是无配置也可能是满额免）、`fee_percent_bps`/`fee_fixed_cents`（费率快照），可完整重建并解释「为何免」。
- `logo_url` **不入订单**（纯展示配置，非财务数据）。
- AutoMigrate 自动加列，默认 0，历史订单=无阈值。

## 3. 计算逻辑（满额免）

### 3.1 后端 `computeFee`（[pricing.go](backend/modules/billing/internal/pricing.go)）

加入阈值参数，命中即免（返回实收手续费）：

```go
// computeFee 实收手续费：base<=0 不收；满额免（threshold>0 且 base>=threshold）则免；否则比例+固定。
func computeFee(baseCents int64, percentBps int, fixedCents, freeThresholdCents int64) int64 {
    if baseCents <= 0 {
        return 0
    }
    if freeThresholdCents > 0 && baseCents >= freeThresholdCents {
        return 0
    }
    return applyBps(baseCents, percentBps) + fixedCents
}
```

`CreateOrder`（[bizorder_service.go](backend/modules/billing/internal/bizorder_service.go)）在 create 前传入阈值并固化 `order.FeeFreeThresholdCents`、`order.FeeCents`。

### 3.2 前端 `money.ts`（[money.ts](my/src/utils/money.ts)）

`computeFeeCents` **维持「原始应收手续费」语义不变**（不含阈值）——用于画删除线展示「本应收多少」。新增谓词：

```ts
// 满额免：阈值>0 且 基数>=阈值。base<=0 时无手续费、不涉及。
export function feeWaived(baseCents: number, freeThresholdCents: number): boolean {
  return freeThresholdCents > 0 && baseCents >= freeThresholdCents
}
```

组件用法：`rawFee = computeFeeCents(base, bps, fixed)`；`waived = rawFee > 0 && feeWaived(base, threshold)`；`actualFee = waived ? 0 : rawFee`；`实付 = base + actualFee`。两端「实收手续费」结果一致（前端 actualFee == 后端 computeFee）。

## 4. 后端 API 与 seed

### 4.1 渠道 logo 上传端点（镜像 partner 模式）

新增 handler `UploadPayMethodLogo`（[billing2_api.go](backend/modules/billing/internal/billing2_api.go)），镜像 [UploadPartnerImage](backend/modules/partner/internal/api.go#L162)：multipart `file` → 校验（≤5MB、png/jpg/jpeg/webp/gif/svg）→ `framework.S3.PutObject(key, ...)`（key `pay-logos/<uuid><ext>`）→ 返回 `{url: framework.S3.PublicURL(key)}`；S3 未配置返回 503。所需的 `maxImageSize`/`allowedImageExt` 在 billing 包内本地定义（modulith 不跨 internal 复用 partner 的常量）。

路由（[module.go](backend/modules/billing/internal/module.go)）：`admin.POST("/payment-methods/upload", staff.PermissionMiddleware("billing:manage"), UploadPayMethodLogo)`。

### 4.2 保存校验（`AdminSavePaymentMethods`）

在现有校验基础上追加：

- `FeeFreeThresholdCents >= 0`，否则 400；
- `code == "balance"`：`FeeFreeThresholdCents` 必须为 0（与 fee 一致，余额无手续费故阈值无意义）。

### 4.3 seed 默认 logo（`defaultPricingConfig`）

- 微信支付 `logo_url = https://cdn.simpleicons.org/wechat/07C160`
- 支付宝 `logo_url = https://cdn.simpleicons.org/alipay/1677FF`
- 余额 `logo_url` 留空（用首字方块回退）。
- 全部 `fee_free_threshold_cents` 默认 0。

> seed 用外部 CDN 作为开箱默认；admin 可上传到自有 S3 后替换，前端 `<img>` 加载失败回退首字方块，CDN 不可达不致白块。

## 6. my 展示（核心）

### 6.1 PaymentBox 每个方式卡片（[PaymentBox.vue](my/src/views/billing/purchase/PaymentBox.vue)）

- **Logo**：左侧若 `m.logo_url` 非空渲染 `<img class="size-6 rounded">`，`@error` 回退到现有 `styleOf(code)` 首字彩色方块；空 `logo_url` 直接用方块。
- **每渠道手续费（只显金额）**：名称下方一行小字，按当前 `amountCents` 计算：
  - 无手续费配置（bps=0 且 fixed=0）→ `t('billing.purchase2.feeNone')`「无手续费」；
  - 满额免（`feeWaived(amountCents, m.fee_free_threshold_cents)` 且 rawFee>0）→ `t('billing.purchase2.feeWaived')`「免手续费」；
  - 否则 → 「手续费 ¥{rawFee}」（`rawFee = computeFeeCents(amountCents, bps, fixed)`）。
  - `amountCents <= 0`（金额未定）时不显示该行。
- 卡片已有 `amountCents` + `methods`（含新字段），自给自足，无需父级额外传参。

### 6.2 结算单手续费行（[OrderSummary.vue](my/src/views/billing/purchase/OrderSummary.vue) 与 [RechargePanel.vue](my/src/views/billing/purchase/RechargePanel.vue)）

把选中支付方式整体传入（扩展 [useQuote.ts](my/src/views/billing/purchase/useQuote.ts) 的 `feeOf` 返回选中 `PaymentMethod`，或父面板直接传 `method` prop），渲染：

- **行首渠道 logo**：选中方式的 `logo_url`（`size-4`，回退首字方块）放在「手续费」标签前。
- **? 气泡提示**：阈值 `> 0` 时，标签后放一个 `?`（`HelpCircle` 图标）触发 shadcn **Popover**（点击/点按打开，C 端多为移动端、比 hover Tooltip 更可靠；my 已有 `components/ui/popover`），内容 `t('billing.purchase2.feeFreeHint', { amount })`「订单金额满 ¥{amount} 免手续费」。
- **删除线**：`waived` 时手续费金额 `<span class="line-through">¥{rawFee}</span>`，实付按不含手续费计算（`payActual = base + (waived ? 0 : rawFee)`）。未满额则正常金额。
- 触发「有手续费分支」的条件改为 `rawFee > 0`（这样满额免时仍显示被划掉的手续费 + ? 提示，清楚表达「已免」）；`rawFee == 0`（纯无配置）维持原「应付总价」突出样式、不显示手续费行。

### 6.3 i18n（zh-CN + en 同步）

- my（`billing.purchase2.*`）：`feeNone`（无手续费 / No fee）、`feeWaived`（免手续费 / Fee waived）、`feeFreeHint`（订单金额满 ¥{amount} 免手续费 / Fee waived on orders ≥ ¥{amount}）。卡片/行的「手续费」标签复用既有 `sumFee`。
- admin（`billing.*`）：`payLogo`（渠道 Logo）、`payLogoUpload`（上传）、`payLogoUrlPlaceholder`（粘贴 logo URL）、`payFeeFreeThreshold`（满额免手续费(¥)）。

## 7. 边界与错误处理

- **向后兼容**：旧配置无 `logo_url`/阈值=空/0；旧订单阈值=0。
- **logo 加载失败**：`<img @error>` 回退首字彩色方块。
- **满额免与基数一致**：阈值比较 `order.TotalCents`，与手续费基数同源；`>=` 即免。
- **余额方式**：fee 与阈值均强制 0（前端禁填、后端校验），逻辑统一不特判。
- **舍入/一致性**：删除线展示的 `rawFee` 用前端 `computeFeeCents`（与后端 `applyBps` 同舍入）；实收以后端 `order.fee_cents` 为准。

## 8. 测试计划

### 后端

- `computeFee` 表驱动追加：满额免（`base==threshold` 边界免、`base==threshold-1` 不免、`threshold==0` 永不免、与比例+固定叠加场景下满额仍免）。
- `CreateOrder` 固化 `FeeFreeThresholdCents`，满额订单 `fee_cents==0`、未满额正常。
- `AdminSavePaymentMethods`：阈值 < 0 拒、balance 阈值非 0 拒。
- `UploadPayMethodLogo`：S3 未配置 503、非法扩展名/超限拒、正常返回 url（可对 S3 用既有测试替身/跳过，与 partner 测试一致）。
- 旧 JSON 无新字段解码为空/0。

### 前端

- `feeWaived`：阈值 0 永不免、`base>=threshold` 免、边界。
- PaymentBox：每方式显示金额/免手续费/无手续费，`amountCents<=0` 不显示；logo 渲染与回退。
- OrderSummary/RechargePanel：渠道 logo、阈值>0 显示 ? 气泡、满额删除线 + 实付不含手续费、未满额正常。
- admin PaymentMethodsView：logo 上传回填 + URL 编辑、阈值 `¥↔cents` 换算、balance 阈值禁用为 0。
